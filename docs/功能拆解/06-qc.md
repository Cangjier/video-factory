## 工具 video_qc

**一句话定位**：`video_qc` 是**成片的验收套件**——把「这条片子能不能交」写成 28 条带 id、期望值、严重级别的可执行用例，对已经渲染出来的 `final.mp4` 跑一遍，逐条给出 `pass / fail / skip` 以及支撑该结论的测量值（`src/tools/qc.mjs:1-21`、`37-45`；`src/core/qc.mjs:868-1234`）。

**何时用**

- 成片渲染完、交付前跑一次 `check`（尽量带上 `plan`）。`ok:false` 就是不要交。
- 只回归已知的几条：`only: [...]`。只选中的用例才会触发对应测量，所以这是最便宜的用法（`src/core/qc.mjs:1341-1370`、`1287-1295`）。
- 报告里某条可疑时，用同族的 `structure` / `picture` 拿原始证据（时间戳、区间）；字幕到底有没有烧上，去 `dsh-ocr` 的 `text_read {action:"verify"}`。
- 想稳定复现判定：所有测量是确定性的（固定采样率、固定阈值并在结果里回显），同一个文件 + 同一份用例文件必然得到同样结论（`src/tools/qc.mjs:12-18`、`src/core/qc.mjs:569-579`）。

**何时不该用**

- 想校验「计划本身字段是否合法、素材是否存在、能不能渲染」→ 那是 `video_plan {action:"check"}`。`video_qc` 不做这件事：`plan` 读不进来时它直接以「计划文件不可用」失败，而不是报告哪条用例不满足（`src/tools/qc-actions.mjs:48-58`）。
- 只想要构建冒烟（分辨率 / 帧率 / 时长 / 有无音轨 / 像素格式 / 文件大小下限）→ `video_inspect {action:"verify"}`，它由 `deliver` 阶段自动跑（`docs/质量检查.md:7-13`）。
- 想判断「好不好看」→ 本族明确不做审美判断，只报事实（`src/tools/qc.mjs:38`）。
- 还没有成片（在选素材、写计划阶段）→ 无可测对象。
- 想查「字幕有没有越界 / 出安全区」→ **本族没有这条用例**（见下）。

### 结构性校验 vs 成片质量检查（本族内部两层，决定调用时机）

| 层 | 是什么 | 用例（id） | 需要的测量 | 什么时候跑最有价值 | 相对代价 |
| --- | --- | --- | --- | --- | --- |
| **结构性 / 交付形态**（17 条） | 容器与流的事实：box 顺序、流数量、画布、帧率、时长、帧数自洽、像素格式、色彩标记、音轨是否存在/是否与画面等长、旁白时序是否落在画面与音轨之内、字幕文本里有没有占位符 | `faststart`、`one_video_stream`、`audio_stream_count`、`width`、`height`、`fps`、`duration`、`frame_count`、`pixel_format`、`color_range`、`color_primaries`、`sample_aspect`、`audio_present`、`audio_duration_matches_picture`、`cues_within_picture`、`cues_within_audio`、`no_placeholder_text` | 2 次 ffprobe（`probe()` + `streamDurations()`）+ 读文件头 + 读 plan/SRT 文本；**不解码** | **每次渲染后立刻跑**：便宜、确定、专门抓「渲染/装配坏了」 | 秒级 |
| **成片质量**（11 条） | 实际排放出来的像素与样本：响度、真峰值、削波、直流偏置、头尾静音、黑帧、冻帧、黑边、交付物是否生成 | `loudness_target`、`true_peak`、`clipping`、`dc_offset`、`head_silence`、`tail_silence`、`black_frames`、`frozen_frames`、`letterbox`、`cover_frame`、`build_report_clean` | 全片音频解码（约 4 遍）、全片画面解码（gray 160×90 @2fps）、读 outDir 下的交付物 | **交付前跑一次**；或结构性用例全绿但仍怀疑「声音/画面本身不对」时定向跑 | 十秒 ~ 分钟级，随时长变化（具体秒数仓库内无基准，未实测） |

两条能证实的关键点：

- 这两层不是两组 action，而是**同一次 `check` 内按 `needs` 惰性取测量**：没被选中的用例不会触发对应测量（`src/core/qc.mjs:1341-1370`）。`only:["faststart"]` 不会解码画面、不会测响度。
- **本族不覆盖「字幕越界」**：28 条目录里与字幕有关的只剩时序（`cues_within_picture` / `cues_within_audio`）与 SRT 文本里的占位符（`no_placeholder_text`），没有任何字幕位置/边界/安全区的几何判定，也没有烧录字幕的像素回读（后者在 `dsh-ocr`）（`src/core/qc.mjs:868-1234` 全表可见，该类计算不存在）。

### 工具级共性语义（所有 action 共用）

- **三态判定**：`pass`（测量满足期望）/ `fail`（不满足）/ `skip`（**期望构不出来或测量取不到**，一定带原因，绝不算通过）。`severity:"error"` 的 fail 让整次 `ok:false`，`"warn"` 默认只记录（`src/core/qc.mjs:478-525`、`1372-1383`；`docs/质量检查.md:15-25`）。
- `ok = (error 级 fail 数 === 0) && (!strict || warn 级 fail 数 === 0)`；`counts = {total, passed, failed, warned, skipped}`，其中 `failed` 只数 error 级（`src/core/qc.mjs:1373-1383`）。
- **只有 6 个比较器**，判定全是算术：`within`（|实际−目标| ≤ 容差）、`atLeast`、`atMost`、`equals`、`runsAtMost`（取最长区间）、`clean`（数组必须为空）（`src/core/qc.mjs:422-449`）。
- 用例文件只能「改阈值、改级别、关用例」，**不能新增判断**；出现目录里没有的 id 会被拒绝而不是静默忽略（`src/core/qc.mjs:1314-1323`）。
- **输出渲染**：`tools/shared.mjs` 的 `TEXT_OUTPUT.render` 只取结果里的 `text` 字段作为工具返回内容（`src/tools/shared.mjs:19-25`）。`check` 的返回对象带 `text`，所以**模型侧看到的是那份纯文本报告，看不到 `counts` / `failures` / `measurements` / `thresholds`**；要结构化数据必须给 `reportPath` 再读文件。`cases` / `structure` / `picture` 都没有 `text` 字段，返回完整 JSON。（宿主是否额外附上原始对象，本仓库无法证实，属未证实。）

### action: cases

- **用途**：列出全部可跑的用例（id、类别、标题、级别、断言方式、依赖哪些测量、是否被用例文件禁用）与默认阈值，用来「对着已知 id 写用例文件」。不读任何媒体（`src/tools/qc-actions.mjs:99-128`）。
- **参数**：

| 参数 | 类型 | 必填 | 默认 | 含义与取值 |
| --- | --- | --- | --- | --- |
| `action` | string | 是 | — | 固定 `"cases"` |
| `casesPath` | string | 否 | 无 | 用例文件；给了就把覆盖后的 `severity` / `enabled` 一起列出来 |
| `cwd` | string | 否 | 插件根/进程 cwd | 解析 `casesPath` 的基准 |

  本 action **忽略** `target`、`plan`、`only`、`skip`、`strict`、`picture`、`reportPath`、`thresholds`、`probeFps`（schema 允许传，handler 不读，`src/tools/qc-actions.mjs:105-128`）。

- **行为细节**：把 `CASE_CATALOGUE`（28 条，`src/core/qc.mjs:868-1234`）映射成条目，`severity = 覆盖值 ?? 目录值`，`enabled = 覆盖的 enabled !== false`，`overrides` 原样回显（`src/tools/qc-actions.mjs:107-116`）。`casesPath` 只做「存在 + 合法 JSON」两步检查（`src/tools/qc-actions.mjs:61-71`）。**本 action 不校验覆盖 id 是否存在**（校验发生在 `runQc` 里，`src/core/qc.mjs:1316-1319`）。
- **输出**：`{action, count, ids[], cases[{id, category, title, severity, compares, needs, enabled, overrides}], defaults(QC_DEFAULTS 全量), casesPath, note}`（`src/tools/qc-actions.mjs:117-127`）。`compares` 是 6 个比较器之一，`needs` ∈ `structure|plan|audio|picture|files`（`src/core/qc.mjs:869-1234`）。
- **代价**：无媒体读取；最多读一个小 JSON。毫秒级。
- **失败与陷阱**：
  - 只用 `cases` 列目录不会发现任何文件问题——它连 `target` 都不看。
  - 拼错的覆盖 id 在 `cases` 里**没有任何提示**（只是永远不会被匹配到），直到你拿同一个文件去 `check` 才报「用例文件里有未知的用例 id」（`src/core/qc.mjs:1314-1319`）。`tests/qc-actions.test.mjs:260-269` 钉住了 `check` 这条行为。
  - 若 `casesPath` 不存在，错误文案里的 action 名是 `check` 而不是 `cases`（`loadCases` 里硬编码，`src/tools/qc-actions.mjs:63`）。
- **典型用法**：
  ```jsonc
  { "action": "cases" }
  { "action": "cases", "casesPath": "qc-cases.json" }
  ```
- **相邻动作**：`cases` → `check`（先拿 id，再写用例文件，再跑 check）。

### action: check

- **用途**：对一份成片跑整套用例，逐条给 `pass/fail/skip` 与 expected/actual/delta。给 `plan` 时期望值来自计划（画布、帧率、时长、响度目标、旁白时序、字幕）；给 `casesPath` 时按文件调阈值/级别/启停（`src/tools/qc.mjs:41`、`src/tools/qc-actions.mjs:130-187`）。
- **参数**（该 action 读取的全集）：

| 参数 | 类型 | 必填 | 默认 | 含义与取值 |
| --- | --- | --- | --- | --- |
| `action` | string | 是 | — | 固定 `"check"` |
| `target` | string | 是（运行时） | — | 成片文件；缺失报 `video_qc check: 需要 "target"。`，不存在报 `找不到文件 <abs>`（`src/tools/qc-actions.mjs:39-46`） |
| `plan` | string | 否（强烈建议） | 无 | 计划；不传则所有依赖 plan 的用例 skip |
| `casesPath` | string | 否 | 无 | 用例文件 |
| `only` | string[] | 否 | 全部 | 只跑这些 id；未知 id 报错 |
| `skip` | string[] | 否 | 无 | 去掉这些 id；未知 id 静默忽略 |
| `strict` | boolean | 否 | `false` | warn 失败也判不通过 |
| `picture` | boolean | 否 | `true` | `false` → 画面类用例 skip，并追加一条 note |
| `reportPath` | string | 否 | 无 | 落盘完整结果的 JSON；目录自动创建 |
| `thresholds` | object | 否 | `QC_DEFAULTS` | 见下面「阈值表」；未知键忽略 |
| `probeFps` | number | 否 | `2` | 写进 `thresholds.probeFps`（`src/tools/qc-actions.mjs:141`） |
| `cwd` | string | 否 | 插件根/进程 cwd | 路径基准 |

  **`ocr` / `sampleFrames` / `matchRatio` 三个参数已删除**（随字幕回读迁到 `dsh-ocr`）。本 action 忽略 schema 里没有的键（`additionalProperties:false` 会先挡住）。

- **行为细节**：
  1. 校验 `target` 存在、`plan` 可加载、`casesPath` 是合法 JSON，然后把 `probeFps` 折叠进 `thresholds`（`src/tools/qc-actions.mjs:136-144`）。
  2. `runQc` 合并 `thresholds = {...QC_DEFAULTS, ...overrides}`，拒绝未知用例 id / 未知 `only` id，选出用例集合（`src/core/qc.mjs:1307-1323`）。
  3. 按 `needs` 惰性取测量：`structure`（2 次 ffprobe + box 扫描）、`files`/`plan`（读 outDir 下的交付物与 SRT 文本）、`audio`（响度/电平/静音）、`picture`（全片灰阶解码）（`src/core/qc.mjs:1341-1370`）。
  4. 逐条 `judgeCase`：先构期望（构不出 → skip + 原因），再测实际（抛错或为 null → skip），再用比较器判定（`src/core/qc.mjs:478-525`）。
  5. 汇总 `counts`/`ok`，`formatQcReport` 生成纯文本；给了 `reportPath` 就 `{...result, casesPath, reportPath}` 落盘（`src/core/qc.mjs:1372-1397`、`1404-1422`；`src/tools/qc-actions.mjs:161-166`）。

### action: structure

- **用途**：把结构性用例背后的**容器原始事实**摊开——每条流的时长/编码/采样率/色彩标记/像素宽高比、容器时长与码率、文件大小，以及 MP4 顶层 box 顺序（据此判断 faststart）。音轨提前结束就是在这里被看见的（`src/tools/qc-actions.mjs:189-220`；`src/core/qc.mjs:150-200`、`86-148`）。
- **参数**：

| 参数 | 类型 | 必填 | 默认 | 含义与取值 |
| --- | --- | --- | --- | --- |
| `action` | string | 是 | — | 固定 `"structure"` |
| `target` | string | 是 | — | 要探测的成片 |
| `cwd` | string | 否 | 插件根/进程 cwd | 路径基准 |

  本 action 忽略 `plan`、`casesPath`、`only`、`skip`、`strict`、`picture`、`reportPath`、`thresholds`、`probeFps`（handler 只读 `target`，`src/tools/qc-actions.mjs:195-198`）。
- **行为细节**：`collectStructure` = `probe()`（容器级 info）+ `streamDurations()`（**第二次 ffprobe**，带 `-show_entries stream=…` 拿每流时长/帧数/色彩字段）+ `scanMp4Boxes()`。box 扫描：先看第 4–8 字节是不是 `ftyp`，不是就 `fastStart:null`（非 ISO BMFF）；随后顺序遍历顶层 box（最多 64 个），支持 32 位、`size===1` 的 64 位 largesize、`size===0` 延伸到文件尾；`fastStart` 由先出现的 `moov`/`mdat` 决定（`src/core/qc.mjs:99-148`、`564-567`）。**不判定**：没有 ok/problems，只给事实。`plan` 相关字段（宽高帧率）在这里也不与计划比较。
- **输出**：`{action, target, container, durationSeconds, sizeBytes, bitRate, width, height, fps, pixFmt, rotation, streams[], videoSeconds, audioSeconds, boxes{fastStart, boxes[], note}, note}`（`src/tools/qc-actions.mjs:198-216`）。
  - `width/height` 是 `probe()` 归一化后的**显示尺寸**（rotation 90/270 时宽高互换），`rotation` 另给（`src/core/probe.mjs:110-128`）。
  - `streams[]`：`{index, type, codec, seconds, frames, fps, sampleRate, channels, bitRate, pixFmt, colorRange, colorPrimaries, colorSpace, sar, dar, width, height}`；`seconds` 不可得时为 `null`（`src/core/qc.mjs:172-190`）。
  - `videoSeconds` / `audioSeconds`：分别取第一条视频/音频流的时长——容器时长可能更长，这正是「音轨提前结束」被发现的地方（`note` 明说，`src/tools/qc-actions.mjs:215`）。
  - `boxes.boxes`：顶层 box 的 `{type, size, at}`；`note` 直接说明 faststart 结论。
- **代价**：2 次 ffprobe + 读文件头（最多 64 个 box 各读 16 字节）。秒级以内，与文件时长基本无关（不解码）。
- **失败与陷阱**：
  - `target` 缺失/不存在 → `video_qc structure: 需要 "target"。` / `找不到文件 <abs>`（`src/tools/qc-actions.mjs:39-46`）。
  - 非 MP4/MOV（例如 webm/mkv）时 `fastStart:null`、`boxes:[]`，**这不是错误**；`check` 里它会变成 `faststart` 用例的 skip（`tests/qc.test.mjs:86-87`）。
  - `streams[].seconds` 为 `null` 很常见（封装没写每流时长）；别把 null 当成 0。
  - 与文档措辞的出入：`docs/质量检查.md:141` 说只跑 `faststart` 时「只做一次 ffprobe」，而代码里 `collectStructure` 固定跑两次 ffprobe（`probe()` 与 `streamDurations()`，`src/core/qc.mjs:564-567`）。
  - 这是**成片的容器结构**，不是「计划结构校验」：计划能否渲染要看 `video_plan {action:"check"}`。
- **典型用法**：
  ```jsonc
  { "action": "structure", "target": "output/final.mp4" }
  ```
- **相邻动作**：`check`（`faststart`/`*_stream*`/`width`/`height`/`fps`/`duration`/`frame_count`/色彩类/音轨时长类用例的原始数据）→ `structure`（要看证据时）。

### action: picture

- **用途**：以**固定采样率**解码画面，报出画面类用例测量的东西：黑帧区间、冻帧区间、边缘黑边比例、亮度统计，全部带时间戳，让「某条警告」可以被人工去看一眼（`src/tools/qc.mjs:43`；`src/tools/qc-actions.mjs:222-246`）。
- **参数**：

| 参数 | 类型 | 必填 | 默认 | 含义与取值 |
| --- | --- | --- | --- | --- |
| `action` | string | 是 | — | 固定 `"picture"` |
| `target` | string | 是 | — | 要采样的成片 |
| `probeFps` | number | 否 | `2`（`QC_DEFAULTS.probeFps`） | 每秒解码多少帧；越高越能发现更短的事件，代价是解码量 |
| `sampleFrames` | number | 否 | `24`（`QC_DEFAULTS.pictureSamples`） | **本 action 里它是「取多少帧来估黑边」**，映射到 `pictureSamples`（`src/tools/qc-actions.mjs:231-234`） |
| `cwd` | string | 否 | 插件根/进程 cwd | 路径基准 |

  本 action 忽略 `plan`、`casesPath`、`only`、`skip`、`strict`、`picture`、`reportPath`、`thresholds`。黑帧阈值与冻帧阈值在本 action 里**不可调**，恒用 `QC_DEFAULTS`（`blackLumaThreshold:16`、`frozenDifferenceThreshold:0`、`probeWidth/Height:160/90`、`maxFrames:4000`），只有 `probeFps` 与 `pictureSamples` 可覆盖（`src/core/qc.mjs:580-589`）。
- **行为细节**：
  - 一次 ffmpeg 解码整片为 `gray` 原始流：`fps=probeFps, scale=160:90`，stdout 以 buffer 收集，上限 `160×90×(4000+1)` 字节，超时 900s（`src/core/sampling.mjs:263-304`）。
  - 黑帧：整帧 luma 均值 ≤ `blackLumaThreshold`(16) 的连续采样帧成段；冻帧：与前一采样帧**逐像素完全相同**（平均绝对差 ≤ `frozenDifferenceThreshold`=0）的连续帧成段（`src/core/qc.mjs:592-594`）。区间端点：结束时间 = 该段最后一帧时刻 + 一个采样间隔，所以单帧段不会被算成 0 秒（`src/core/qc.mjs:251-262`；`tests/qc.test.mjs:93-105`）。
  - 黑边：在**均匀分布的最多 `pictureSamples` 帧**上估；一行/一列要「极差 ≤ `barLumaTolerance`(24)」**且**「画面中部均值 − 该行/列均值 ≥ 24」才算黑边；上下左右各自向里推进，最多到一半尺寸（`src/core/qc.mjs:304-365`、`596-611`）。返回的是**最严重的那一帧**（含 `bars.at`），不是平均。
  - 亮度统计：采样帧 luma 均值的 mean / darkest / brightest。
  - 确定性：同一文件 + 同一 `probeFps` 两次运行得到同样的时间戳与区间（固定采样率与探测尺寸，`src/core/qc.mjs:569-579`）。
- **输出**：`{action, target, probeFps, width, height, sampledFrames, luma{mean,darkest,brightest}, blackLumaThreshold, blackRuns[{fromSeconds,toSeconds,seconds,frames}], frozenDifferenceThreshold, frozenRuns[…], bars{top,bottom,left,right,at,note}, note}`（`src/core/qc.mjs:613-628`；`src/tools/qc-actions.mjs:236-242`）。`bars` 的四个值是**相对画面自身尺寸的比例**（0.03 = 3%），`at` 是最严重帧的时刻。
- **代价**：1 次全片解码（默认 2fps、160×90 代理）；`probeFps` 翻倍基本就是解码量翻倍。上限：4000 帧（默认 ≈2000s 视频）、900s 墙钟。
- **失败与陷阱**：
  - **没有 ok / problems / 判定**：这里只有事实与阈值回显。要不要因此不交付，由 `check`（`black_frames`/`frozen_frames`/`letterbox` 三条）说。
  - **`sampleFrames` 在这里是「取多少帧估黑边」**（`pictureSamples`）；`check` 历史上那个「回读多少条字幕」的含义已随字幕回读迁出，本族现在只有这一种含义。
  - `sampleFrames`/`pictureSamples` **只影响黑边**：黑帧、冻帧用全部采样帧判定（`src/core/qc.mjs:592-602`）。
  - **黑边只报最严重的一帧**：其余帧的黑边不会列出来，只有一个 `bars.at` 供回看。
  - 采样是采样：默认 2fps，短于约 0.5s 的事件可能看不见；提高 `probeFps` 才看得见，代价是解码时间（`docs/质量检查.md:187`）。
  - 超过 4000 帧时 ffmpeg 被 kill，本 action **以工具失败收场**（错误文案含「标准输出超过 … 字节上限」），不是返回部分结果（`src/core/ffmpeg.mjs:187-196`）。
  - 有意做的静止镜头一定会出现在 `frozenRuns` 里——那是定义，不是缺陷（`src/core/qc.mjs:1192-1193`）。
- **典型用法**：
  ```jsonc
  { "action": "picture", "target": "output/final.mp4" }
  { "action": "picture", "target": "output/final.mp4", "probeFps": 4 }
  ```
- **相邻动作**：`check` 里 `black_frames`/`frozen_frames`/`letterbox` 报 warn 后，用本 action 拿时间区间去回看画面。

### 已迁出到 dsh-ocr：原 `action: subtitle_ocr`（与用例 `burned_in_readable`）

**这个 action 不在本插件里了。** 烧录字幕的回读现在是独立插件 **`dsh-ocr`**（`C:\Users\Admin\Documents\GitHub\dsh-ocr`，工具族 `text_*`）的 **`text_read {action:"verify"}`**：按 `plan.subtitles.source` 指的 SRT，在**字幕应当可见的时刻**抽帧读字，逐条比较「本该在屏幕上的字」与「实际读回来的字」，给出相似度与 `mismatches`。`check` 里的 `burned_in_readable` 用例也一并迁走，本族不再有它；本族剩下的 `no_placeholder_text` 只查 SRT 文本（不抽帧）。

下面几条是当年在本仓库实测出来的结论，留作历史记录（实现已随能力迁到 `dsh-ocr`，结论仍然成立）：

- 比较前先做全角→半角、去掉所有空白/标点/符号、转小写；相似度 = 归一化后**最长公共子序列长度 ÷ 较长者长度**（`src/core/qc.mjs:376-410` 是迁出前的位置）。
- **比较对象是「最像的那一个候选」**：读到的每一行、每相邻两行拼接（字幕折行）、以及整帧文本，取最高分，命中类型记在 `matchedLine`（`line`/`pair`/`frame`/`empty`）。这是为了教学类视频「满屏界面文字 + 一行字幕」的场景：拿整帧去比会把烧对字幕算成 0.03。每帧的整帧读文仍完整保留在 `read` 里，证据不丢。
- **读不出来也长得像没问题**：`error` 存在时 `cues` 为空、`mismatches` 为空；字幕没启用或 `source` 不是可读 SRT 时返回 `sampledCues:0` 且没有 `ok:false`。所以必须看 `error` / `sampledCues` / `minSimilarity === null`，而不是只看「有没有 mismatches」。
- 相似度是按字符的 LCS：改一个字（「任务」→「住所」）仍有 0.7+ 的高分，所以 0.6 的门槛只抓「缺行/大段错」；反过来，短字幕被多读几个字也会掉分。
- 折行字幕靠「相邻两行拼接」候选兜住；若被拆成三行以上、或行的顺序被打乱，可能匹配失败。

要逐条回读，用 `dsh-ocr` 的 `text_read {action:"verify", target:"output/final.mp4", plan:"plan.json"}`；本仓库已无这段代码、无 `subtitle_ocr` action、也没有 `ocr` / `sampleFrames` / `matchRatio` 三个参数。
