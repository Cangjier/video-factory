# 素材 → 成片：技术方案调研报告

> 调研日期：2026-10-02 ｜ 调研对象：本机（Windows 10 LTSC 19044 x64，无 NVIDIA GPU，中国大陆网络直连）
> 配套落地实现：`C:\Users\Admin\Documents\GitHub\video-factory`（已跑通端到端）

---

## 0. 结论先说

**不存在"一个模型把素材丢进去就出片"的单一方案。** 可行且性价比最高的是一条**混合流水线**：

```
                 ┌──────────────────────────────────────────────┐
   素材          │  1. 素材盘点（ffprobe + 感知哈希去重）        │
   ├ 图片  ─────▶│  2. DSH 决策：写剪辑计划 plan.json           │  ← 创意在这里
   ├ 视频片段    │  3. 本地 ffmpeg 确定性渲染                    │
   ├ 音频/音乐   │     · 统一规格 → 转场 → 调色/运镜 → 混音      │
   ├ 文案   ─────▶│     · 云端只用于「凭空生成缺失镜头」          │
   └ 主题词      │  4. 导出 + 封面 + 缩略图 + 验收报告           │
                 └──────────────────────────────────────────────┘
```

三条关键判断：

1. **剪辑合成必须是本地的、确定性的。** 云端没有"把 6 张图加一段音乐合成一条片子"这种 API，也不该有——这类工作 ffmpeg 做得又快又好，而且零成本、可复现。本机实测：**36.4 秒竖屏成片，1080×1920@30，含中文烧录字幕与自动配音，全流程 55–70 秒。**
2. **AI 生成只用来补"拍不到的画面"，不要用来做全片。** 全片生成 60 秒 1080P 约 **¥60**（万相 2.5 定价 ¥1/秒），而混合方案（本地剪辑 + 2–3 个生成镜头）通常 **¥3–5**。
3. **国内直连的首选是阿里百炼 DashScope**，一个 Key 同时覆盖通义万相和转售的 PixVerse，异步 create/poll 契约统一，个人实名即可开通。

## 1. 需求拆解

你选了"都有可能"，所以方案必须覆盖全部四种组合：

| 视频类型 | 主要矛盾 | 主力手段 | 是否需要 AI 生成 |
| --- | --- | --- | --- |
| 素材剪辑合成片 | 节奏、转场、音画对位 | 本地 ffmpeg | 否 |
| AI 生成镜头 | 画面不存在 | 云端 t2v / i2v | 是 |
| 数字人口播 | 形象一致性 + 时长 | 云端 s2v（有硬限制） | 部分 |
| 图文成片 | 文案 → 分镜 → 配音 | 本地 + TTS | 否 |

| 素材形态 | 处理方式 |
| --- | --- |
| 本地素材文件夹 | ffprobe 盘点 → 感知哈希去重 → 自动排序 → 生成计划草案 |
| 一段文案 | Edge TTS 配音 + 逐词时间戳 → 字幕；字数决定镜头时长 |
| 一个主题/关键词 | DSH 联网检索/取图（需自备图库 API），再走文件夹路线 |
| 已有长视频 | ffmpeg 切片 + 卡点重排（`trim` + 变速 + 重拼接） |

## 2. 路线对比

| 路线 | 成本 | 质量上限 | 可复现 | 本机可行性 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **本地 ffmpeg 剪辑** | 0 | 取决于素材 | ✅ 完全 | ✅ 已跑通 | **必选底座** |
| **云端 API 生成** | ¥0.3–1.2/秒 | 高 | ❌ 同 prompt 不同结果 | ✅ 需 Key | **按需补镜头** |
| 本地生成模型（Wan/HunyuanVideo） | 电费 | 中 | 一般 | ❌ **无 GPU，排除** | 不采用 |
| 现成 SaaS（剪映/智影等） | 订阅 | 高 | ❌ | ❌ 无 API 或已停服 | 不采用 |

**为什么排除本地生成模型：** 本机无 NVIDIA GPU（`nvidia-smi` 不存在）。Wan 2.2 / HunyuanVideo 等开源模型即便量化后也需要 12–24GB 显存。CPU 推理一条 5 秒 720P 片段是小时级，不构成可用方案。

**为什么排除 SaaS：** 腾讯智影域名 `zenvideo.qq.com` 当前 DNS 解析到 `0.0.1` 且 HTTPS 超时——**服务已不可用**，网上大量仍然推荐它的教程是过期的。HeyGen 的 `api.heygen.com` 从国内 TCP 不可达，其官网明确标注需海外网络。

### 3.4 接入时必须注意的坑

- **百炼域名正在迁移**：`https://dashscope.aliyuncs.com/api/v1` → `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1`。旧域名仍可用，但**端点、模型、Key 必须同区域**，否则调用失败。本实现的 base URL 是配置项而非常量。

- **OpenRouter 在国内直连不可用**，官方指引明确要求稳定代理。已排除。

## 4. 配音、字幕与数字人

### 4.1 配音（TTS）

本机已实测：**edge-tts 7.2.8 直连可用，无需 Key**。一段 89 词的文案产出 33.45 秒配音 + 9 条字幕，逐词时间戳准确。

> ⚠️ **商用授权风险（重要）**：微软在 2026-09-29 的官方问答中表示，**未发布任何文档授予 Edge 朗读/edge-tts 输出的商业再分发权利**，并指向 Azure AI Speech 作为商用路径。**草稿、个人内容可用；要卖的内容请换掉。**

商用替代（价格已核实）：

| 服务 | 价格 | 备注 |
| --- | --- | --- |
| 阿里 CosyVoice-v3-flash | **$0.14335 / 万字符** | 北京区，5–20 秒参考音频即可克隆，RPM 180 |
| MiniMax 预置包 | Turbo ¥360 / 200 万字符；HD ¥630 / 200 万字符 | RPM 60 |
| 火山引擎 | 未验证（官方价格页未渲染） | 二手来源 ¥0.02–0.05/千字 |

**设计上的关键取舍：不要依赖云 TTS 返回时间戳**（各家的时间戳 API 均未验证）。本实现的做法是**按句合成 / 用逐词边界事件自己算时间**，时间轴完全自己掌握。

### 4.2 字幕

两条路：

- **有文案** → 用 TTS 的逐词边界直接生成 SRT，零成本、零延迟。**这是默认路径，已实现。**
- **只有音频/视频** → 需要 ASR。最优是**阿里百炼 Paraformer**：**¥0.00008/秒**，仅按检测到的语音时长计费，另有 **每月 36,000 秒（10 小时）免费额度**。5 分钟片子约 ¥0.024，大概率完全免费。**比本地跑 Whisper 的电费还便宜。**

本地替代（faster-whisper 1.2.1，CPU int8，i7-12700K 实测 13 分钟音频约 1 分 42 秒）存在两个问题：模型要从 HuggingFace 下载（**国内不可达**，必须走 ModelScope 镜像），且中文词级时间戳不如强制对齐准。**不推荐作为首选。**

卡拉 OK 式逐字高亮用 ASS 的 `\k` 标签（单位厘秒，每个汉字一个），可用 `pysubs2` 程序化生成。

### 4.3 数字人

**不推荐作为默认路线。** 唯一国内可直连的可行选项是阿里 **通义万相 `wan2.2-s2v`**（人像 + 音频 → 口型同步视频，异步，480P $0.071677/s、720P $0.129018/s），但有两个硬限制：

- **音频必须 < 20 秒**，超了任务直接失败；
- **并发上限 1**。

一条 5 分钟的口播视频 = 约 15 个串行片段 = **2–2.5 小时**，还不含拼接。成本约 ¥22。

本地数字人方案（SadTalker / Wav2Lip / EchoMimic / LatentSync）全部是 GPU 密集型，本机无法运行。

**默认应走"配音 + 空镜/生成 B-roll + 字幕"**：更便宜、没有 20 秒天花板、没有并发限制。

### 4.4 合规（硬性）

《人工智能生成合成内容标识办法》自 **2025-09-01** 起施行，要求 AI 生成内容添加**显式 + 隐式标识**，且**禁止删除或遮挡**。克隆他人肖像/声音需取得书面同意（国内法院已认可声音权延伸至 AI 合成声音）。

> 本报告的合规条文内容来自调研，**未能亲自核验法规原文**。面向公开发布的产品化部署前，请自行核对现行文本。

## 5. 已落地的架构

### 5.1 设计原则：创意与执行分离

**DSH 写 `plan.json`，Python 用 ffmpeg 确定性执行。** 这一条是整个方案的核心。

- 计划是小的、可读的、可 diff 的、可复跑的；
- 执行是纯函数式的：同样的计划永远出同样的片子；
- 失败能定位到具体阶段和具体字段。

### 5.2 流水线四阶段

| 阶段 | 做什么 | 产物 |
| --- | --- | --- |
| **normalize** | 每个镜头统一到同一画布/帧率/像素格式/时间基，且**音轨长度精确等于镜头时长**（无音源则填静音） | `work/scenes/NNN_id.mp4` |
| **assemble** | 无转场走 concat demuxer 流复制（快且无损）；有转场走单条 `filter_complex` 串 `xfade`/`acrossfade` | `work/timeline.mp4` |
| **finalize** | 配音 + 音乐混音（`sidechaincompress` 自动闪避）、EBU R128 响度归一、字幕烧录——**视频最多重编码一次** | `output/final.mp4` |
| **deliver** | 封面帧、缩略图总览、验收报告 | `cover.jpg` / `contact-sheet.jpg` / `build-report.json` |

**为什么先统一规格：** concat demuxer 对 `time_base`、SAR、pix_fmt、音频采样率任何一项不一致都会静默出错——不是报错，而是画面卡住、音频错位、播放器在接缝处停下。统一规格是让所有后续操作安全的前提。

### 5.3 本机实测数据

| 指标 | 实测值 |
| --- | --- |
| ffmpeg | `N-127054-g9d3f0f2c58-20261001`，GPL 静态构建 198MB |
| 编解码器 | libx264 ✅ libx265 ✅ aac ✅ |
| 滤镜 | subtitles ✅ ass ✅ drawtext ✅ zoompan ✅ xfade ✅ loudnorm ✅ |
| **fontconfig** | ❌ **缺失**（因此字体必须显式指定） |
| Python | 3.12.14（独立 venv） |
| 配音 | 89 词 → 33.45 秒，9 条字幕，无需 Key |
| 成片 | 5 镜头，1080×1920@30，36.4 秒，2.68MB |
| 全流程耗时 | **55–70 秒**（quality=medium） |

### 5.4 三个只有踩过才知道的坑（均已在实现中修正）

1. **`-nostdin` 而不加 `-y` 会导致重跑失败。** 输出文件已存在时 ffmpeg 要交互确认，`-nostdin` 让它无法回答，于是退出码 1，而 stderr 里只有一行不起眼的 `Duration:`。首次运行成功、`--force` 重跑失败——非常难查。
2. **`edge-tts` 7.x 默认返回 `SentenceBoundary` 而不是 `WordBoundary`。** 按 `WordBoundary` 过滤会拿到空列表，表现为"合成失败"，但音频其实已经写出来了。必须显式传 `boundary="WordBoundary"`。
3. **本机 ffmpeg 没有 fontconfig，且中文不能内联进滤镜串。** `drawtext=text='中文'` 会静默渲染成空白（PowerShell 写文件时的 UTF-8 BOM 会加剧这一点）。正确做法是把字体和文本都**拷贝到工作目录、用相对 ASCII 路径引用**，文本走 `textfile=`。这样同时绕开了 Windows 盘符 `C:` 的冒号被滤镜解析器当作选项分隔符的问题。

## 6. 成本测算

以一条 **60 秒竖屏短视频** 为例：

| 方案 | 计算 | 成本 |
| --- | --- | --- |
| **纯本地剪辑**（素材齐全） | ffmpeg | **¥0** |
| **混合：本地剪辑 + 3 个生成镜头**（推荐） | 3×5s × ¥1.0/s（万相 1080P） | **¥15** |
| 混合 + 商用配音 | + 约 1000 字 × CosyVoice | **+¥0.10** |
| 混合 + ASR 字幕 | 5 分钟语音 × ¥0.00008/s | **+¥0.024**（大概率落在免费额度内） |
| 全片 AI 生成 1080P | 60s × ¥1.0/s | **¥60** |
| 全片生成（省钱档） | Vidu Q3-Turbo 540p 错峰 ¥0.125/s | **¥7.5**（质量下降，延迟可达 48h） |
| 数字人口播 5 分钟 | wan2.2-s2v 480P，15 段串行 | **约 ¥22 + 2–2.5 小时** |

**结论：把 AI 生成限制在"补几个关键镜头"，成本能压到全片生成的 1/4 以下，而观感提升主要来自本地剪辑的节奏和字幕。**
