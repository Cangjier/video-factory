# 工具重组方案（v2.1）

> 目标：让 DSH 在**每一轮**都能看到足够多的决策信息，同时不让「详细信息」变成每轮都要付的固定成本。
> 结论：**常驻 schema 基本持平（47.9 KB → 48.7 KB），可检索的详细信息从 0 增加到约 46 KB**（`video_guide` 五个动作按需返回），并且顺带修掉了拆解过程中发现的几个真实缺陷。

## 一、重组前后对照

| 重组前 | 重组后 | 为什么 |
|---|---|---|
| `video_env`（7 action：`probe` `presets` `scan` + 4 个 `install_*`） | `video_env`（`probe` `presets` `scan`）+ **`video_setup`**（4 个 `install_*`；2026-10-04 起 `install_ocr` 随 OCR 能力迁出到独立插件 `dsh-ocr`，现为 3 个） | 只读环境检查与「下载几百 MB / 卸载安装」不该是同一个 enum 里的相邻选项；一次误选就是一次下载 |
| `video_audio`（12 action、38 参数） | **`video_audio_build`**（`tone` `assemble` `restore` `record`）+ **`video_audio_measure`**（`identify` `speech_map` `loudness` `levels` `integrity` `sync` `noise` `devices`） | 工具名即意图；两个 schema 各自只声明自己 action 用到的参数，参数归属可见 |
| `description` 与 `action.description` 写同一段文字 | tool description = 定位/适用/前置/下一步；action 行 = 产出 + 必填参数 +（能放下的）最易犯的错 | 同一段话原来在一份 schema 里出现**两次**：实测重复 9 339 字符（≈2.3k tokens/轮），删掉后信息量为零损失 |
| 详细参数说明、返回值、耗时、陷阱、示例散落在 schema 与 README | 全部结构化进 `src/tools/registry.mjs`，由 **`video_guide`** 按需渲染 | schema 里放不下的细节，现在可以「想多详细就多详细」，而不进每轮上下文 |
| 无跨工具知识 | **`video_guide {action:"rules"}`**：决策边界、确定性契约、缓存与 `force` 真相、plan.json 写法、成本与可用性矩阵、症状→动作排查表；**`{action:"playbook"}`**：8 条端到端流程 | 原来只写在 README 里的隐性知识，现在模型能自己查到 |
| `video_analyze` 的 `duration` 键重复声明（后者覆盖前者） | 合并为一条，同时说明 `audio_events` 与 `matte_status` 两种语义 | 模型此前只能看到 `matte_status` 的解释，`audio_events` 的 `duration` 语义在 schema 里等于不存在 |

重组后的 12 个工具与顺序（也是 `video_guide {action:"overview"}` 的顺序）：

```
video_guide → video_env → video_setup → video_plan → video_narrate → video_analyze
→ video_gen → video_render → video_inspect → video_qc → video_audio_build → video_audio_measure
```

共 **12 工具 / 53 action**（重组前 9 / 53，净增 `video_guide` 的 5 个参考动作，其余动作只是换了归属；数字按 2026-10-04 的代码重数——本次重组当时是 58 个 action，随后的 OCR 迁出带走了 5 个：`install_ocr`、`video_inspect` 的 `ocr`/`find_text`/`ocr_status`、`video_qc` 的 `subtitle_ocr`）。

## 二、四条设计原则（可检查）

1. **单一事实来源。** `src/tools/registry.mjs` 是唯一的散文来源；`shared.mjs` 从它派生 tool description 与 action 行，`video_guide` 从它渲染完整参考。三者不可能互相矛盾。
2. **双向强制一致。** `defineFamilyTool` 在加载时校验：注册了但未登记、登记了但未注册、声明了但没有 handler —— 三种情况都直接抛错；`tests/surface.test.mjs` 再独立断言一次。**改代码忘改文档**这件事从此不可能悄悄发生。
3. **常驻只放「选择所需」，细节一律按需。** action 行有 215 字符预算，按「产出 → 必填参数 → 最易犯的错 → 何时用」优先级填充，放不下的进 guide；`tests/surface.test.mjs` 用字节预算（< 52 KB）和单行上限（300 字符）把这个纪律钉住。
4. **按用途切分，而不是按实现切分。** `build` / `measure` 的分界是「你要造声音还是要量声音」，不是「用了哪组 ffmpeg 滤镜」；`env` / `setup` 的分界是「读事实还是改磁盘」。

## 三、详细度去了哪里

`video_guide` 五个动作，全部是纯计算、零网络、零磁盘：

| 动作 | 内容 | 实测篇幅 |
|---|---|---|
| `overview` | 12 工具 × 53 action 的一页索引，带 `requires` 标注 | ~15 KB |
| `rules` | 10 组全局规则：谁做决定、不要自己拼 ffmpeg、确定性矩阵、缓存与 `force`、生成物、plan.json 写法、成本与可用性、质量闸门、输出可见性、症状→动作 | ~8 KB |
| `playbook` | 8 条流程（竖屏口播短片 / 图集 / 长素材剪辑 / 生成补镜头 / 声音优先 / 成片诊断 / 只做字幕 / 环境补齐），每条含步骤、分支与「哪里会翻车」 | 1.6 KB（列表）/ 1.9 KB（单条） |
| `tool` | 单工具全解：定位、何时用/何时别用、前置、下一步、**参数表（类型 / 哪个 action 必填 / 含义）**、每个 action 的用途-必填-返回-耗时-陷阱-示例-相邻动作 | ~8–12 KB |
| `action` | 单 action 全解 + 完整示例 | ~1.5 KB |

一次性全读约 46 KB；实际使用通常只读 `overview`（一次）+ 关键 `action`（若干次）。

## 四、成本账（实测）

| 指标 | 重组前 | 重组后 | 变化 |
|---|---|---|---|
| 工具数 / action 数 | 9 / 53 | 12 / 58 | +3 / +5（参考动作） |

> 下表的字节数与 action 数都是**当次重组当时的实测**，保留原样；2026-10-04 的 OCR 迁出之后，live 的 action 数是 **12 / 53**（见上一节），常驻 schema 字节数也会相应变小，没有重新测量。
| description 合计 | 12 088 字符 | 7 161 字符 | −41% |
| action enum 说明合计 | 9 339 字符 | 10 806 字符 | +16%（多了必填参数与关键陷阱） |
| 其中重复文本 | 9 339 字符 | **0** | 归零 |
| 模型每轮可见 schema | 47 883 B | **48 689 B** | **+1.7%（基本持平）** |
| 可检索细节 | 0 | ~46 KB（`video_guide`） | 新增 |

复现：`node src/bin/surface-report.mjs`（逐工具列出字节数与最长 action 行；同样的数字由 `tests/surface.test.mjs` 断言，超预算即失败）。

> 说明：这轮**没有**追求把常驻 schema 压小，而是把「详细」从常驻搬到可检索，并把省下的重复开销换成每行都有的**必填参数**。若你希望常驻再降 20–30%，可把 action 行砍到「产出 + 必填」，全部「何时用/何时别用」只留在 guide —— 代价是模型选 action 时要多一次 guide 调用。

## 五、行为不变的部分（可回归）

- 所有原有 action 名、参数名、参数语义、返回结构、错误文案**未改**（仅 7 处错误文案把 `video_env {action:"install_*"}` 改成 `video_setup {action:"install_*"}`，因为它们指向的安装动作换了工具）。
- CLI（`node src/bin/vf.mjs …`）未改：它本来就是同一批核心操作的命令行壳，与工具分组无关。
  - **后续（2026-10-04，OCR 迁出）**：这一条不再完全成立——`install-ocr` 与 `ocr` 两个子命令随 OCR 能力删掉了，CLI 现在是 **16 个子命令**；其余命令与参数未动。
- `plan.json` 格式、渲染结果、缓存语义**未改**（缓存那条「按文件存在复用、不是指纹」的真相此前只写在注释里且与实现不符，现在写进了 registry 与 guide，并被 `video_render` 的 `force` 说明引用）。
- 回归证据：`node --test "tests/*.test.mjs"` → **327 项全绿**，其中新增 `tests/surface.test.mjs` 8 项专门看守这次重组的纪律。

## 八、被否决的方案

**用 DSH 原生 `deferLoading` 做惰性工具加载。** 证据：harness 的 Anthropic 路线会把 `deferLoading:true` 映射成 `defer_loading:true`，但 pi-ai 适配器一旦遇到声明了 `deferLoading` 的工具会直接抛 `LlmError("Deferred tool loading is not supported yet", "UNSUPPORTED_CONTENT")`（app.asar 内 `lib/types/transport.js` 与 pi-ai 转换层）。当前会话路线的适配器不确定，一旦命中就是**整轮请求失败**。风险远大于收益，故改用 `video_guide` 这一层「按需读取」。
