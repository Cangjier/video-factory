# video-factory DSH 插件设计规格

> 状态：**待评审**（评审通过后才动代码）
> 日期：2026-10-02
> 关联：[../README.md](../README.md)

---

## 0. 一句话

把 video-factory 从「一个 Python CLI + 一份教 DSH 怎么用的 skill」改造成
**一个纯 Node 的 DSH 插件：插件只提供确定性工具，流程与创作决策全部由 DSH 负责。**

```
之前：  skill（流程知识，靠模型自觉遵守） → CLI（流程也写死在 run/draft_plan 里）
之后：  video_* 工具（只做「同输入必得同输出」的事） ← DSH 自己决定什么时候调哪个
```

---

## 1. 目标与非目标

### 1.1 目标

| # | 目标 |
| --- | --- |
| G1 | 插件是一个标准 DSH bundle，能通过 `link:` 装进 profile，热加载后 `video_*` 工具直接可用 |
| G2 | **执行层完全用 Node 重写**，删掉 `video_factory/` Python 包、`.venv`、`requirements.txt` |
| G3 | 工具集只包含确定性操作：给定相同输入，必得相同输出（云生成除外，见 G5） |
| G4 | 流程编排权完全交给 DSH：插件里不存在 `run` 一键流程 |
| G5 | 云生成只支持**字节跳动火山方舟**一家 |
| G6 | 插件零第三方运行时依赖（只用 Node 内置模块 + 全局 `fetch`） |
| G7 | 删掉 `~/.agents/skills/video-factory/`，工具描述取代它作为唯一入口 |

### 1.2 非目标

- **不做** `draft_plan` / `suggest_scene_order` / `_fit_to_duration` 这类"替 DSH 做创作判断"的工具。
  草案排序、节奏、转场选择、镜头时长，都是创作决策，归 DSH。
- **不做** `run` 一键流程。
- **不做** 多厂商云生成抽象层。只做字节跳动，不为不存在的第二家留接口。
- **不做** 兼容层。Python 版直接删，不保留"双跑对照"。
- **不引入** 构建步骤（不用 TypeScript 编译）。纯 ESM，`node --check` 可校验。

## 2. 职责边界（本设计的核心）

### 2.1 DSH 负责

- 听完需求决定成片形态：竖屏/横屏、时长、节奏、镜头顺序
- 读素材清单做取舍：用哪几张图、哪几段视频、哪首 BGM
- 写 `plan.json` **全文**（插件只校验，不生成）
- 决定什么时候配音、什么时候生成镜头、什么时候渲染
- 渲染失败后决定改计划重跑还是只重跑某一阶段
- 向用户交付、解释创作决策、翻译 `problems`

### 2.2 插件负责

- 把素材目录变成**结构化清单**（枚举、探测、去重、分类）
- 把文案变成**配音文件 + 逐词时间戳 + 字幕文件**
- 把 `plan.json` 变成**校验结果 + 精确时长**
- 把**单个镜头**渲染成规格统一的中间片段
- 把片段**拼接**成时间线
- 把时间线 + 音频 + 字幕**合成**成 `final.mp4`
- 出封面、缩略图、验收报告
- 检查成片是否符合计划
- 向字节跳动**提交生成任务、轮询、落盘**

### 2.3 判据：一个操作该不该做成工具？

问三个问题，三个都是"是"才做：

1. **同样输入是不是必得同样输出？**（`scan` 是；`draft_plan` 不是——它替 DSH 排了序）
2. **它是不是只做执行、不做选择？**（`render_scene` 是；`fit_to_duration` 不是）
3. **去掉它，DSH 是不是就得自己拼 ffmpeg 命令行？**（是→必须做，因为字体/转义/时间基的坑不能再让 DSH 踩）

## 3. 架构

### 3.1 分层

```
┌──────────────────────────────────────────────────────────┐
│ DSH（流程与创作决策）                                      │
└───────────────┬──────────────────────────────────────────┘
                │ 调用 video_* 工具
┌───────────────▼──────────────────────────────────────────┐
│ index.mjs          插件入口：apply / inject / 注册工具      │
│ src/tools/*.mjs    工具定义：JSON Schema + execute + render │
└───────────────┬──────────────────────────────────────────┘
                │ 纯函数调用（同进程，无 subprocess）
┌───────────────▼──────────────────────────────────────────┐
│ src/core/*.mjs     确定性内核（无 DSH 依赖，可单测）         │
│   plan / scene / filter / assemble / finalize / audio /    │
│   materials / ffmpeg / probe / tts / srt / ark             │
└───────────────┬──────────────────────────────────────────┘
                │ 参数数组（绝不用 shell 字符串）
┌───────────────▼──────────────────────────────────────────┐
│ ffmpeg / ffprobe（vendor/ffmpeg/bin）+ Edge TTS + 火山方舟  │
└──────────────────────────────────────────────────────────┘
```

**为什么内核不依赖 DSH**：`src/core/` 是纯 ESM，可以被 `node --test` 直接单测，也可以被将来的 CLI 复用。
`src/tools/` 是唯一知道 DSH 存在的层。这条边界让"确定性"可验证。

### 3.3 插件契约

```js
// index.mjs
export const name = 'video-factory'          // Cordis 插件名
export const inject = ['tools']              // 需要 tools 服务
export function normalizeConfig(raw) { ... } // 自己校验配置，错就抛
export function apply(ctx, rawConfig) {
  const config = normalizeConfig(rawConfig)
  ctx.inject(['tools'], (toolsCtx) => { registerTools(toolsCtx, config, ctx.logger) })
}
```

配置项（`cordis.patch.yml` 出厂默认）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `projectRoot` | 插件自身位置 | ffmpeg 与默认工作目录的基准；换机器不用改 |
| `ffmpegPath` / `ffprobePath` | `null` | 显式指定二进制，覆盖发现顺序 |
| `ark.baseUrl` | `https://ark.cn-beijing.volces.com/api/v3` | 火山方舟 API 根（见 §7） |
| `ark.apiKeyEnv` | `ARK_API_KEY` | Key 走环境变量，不写进配置 |
| `ark.defaultModel` | 见 §7.2 | 默认模型 ID；**唯一会变的是这一处**，模型上下线靠 `models` action 动态发现 |
| `ark.pollIntervalSeconds` | `15` | 轮询间隔（官方示例即为 15s） |
| `ark.maxWaitSeconds` | `900` | 单任务放弃阈值 |
| `tts.voice` | `zh-CN-XiaoxiaoNeural` | 默认音色 |
| `ocr.enginePath` | `null` | 显式指定 OCR 引擎可执行文件，覆盖发现顺序 |
| `ocr.source` | `null` | 已安装引擎里优先用哪一个（`rapidocr-json` / `paddleocr-ppocrv5`） |
| `ocr.defaultEngine` | `auto` | `auto` = 离线引擎优先、失败退回 WinRT；也可 `local` / `winrt` |
| `ocr.maxSideLen` | `1024` | 交给引擎的长边像素上限，调小更快 |
| `ocr.timeoutMs` / `ocr.idleMs` | `180000` / `120000` | 单张识别超时；空闲多久后退出引擎（释放常驻内存） |
| `ocr.scale` | `null` | 默认放大倍数；`auto` = 小图放大到长边约 1000px（见 §13） |
| `pathBudget` | `200` | 中间产物路径长度上限（Windows 260 限制） |

## 4. 工具清单

### 4.1 为什么是 7 个工具而不是 30 个

每个工具的 JSON Schema 都会在**每一轮**进入模型上下文。30 个细粒度工具 = 每轮多花几千 token，
而 DSH 真正需要的是"操作 + 参数"，不是"操作名当工具名"。

所以：**按操作族分组，族内用 `action` 分派**——和 `mail_notify` 用 `action` 分派 status/guide/test 是同一个模式。
7 个工具、36 个 action，schema 总量和 7 个中等工具相当。

代价是 action 列表必须**穷尽且自解释**：每个 action 的 description 里写清"输入什么、输出什么、什么时候用"，
不能让 DSH 猜。这是下面每个 action 表都要写全的原因。

### 4.2 总览

| 工具 | action 数 | 覆盖 |
| --- | --- | --- |
| `video_env` | 7 | 环境自检、预设、素材清单、装 ffmpeg、装 OCR 引擎、装音频事件模型、装抠像模型 |
| `video_narrate` | 6 | 配音、时间戳、字幕、语音转文字 |
| `video_plan` | 4 | 计划校验、时长、字段速查、诊断 |
| `video_render` | 5 | 单镜头、拼接、合成、交付、整链 |
| `video_inspect` | 5 | 成片验收、媒体元信息、读图取字、定位文字、OCR 状态 |
| `video_gen` | 4 | 方舟模型发现、生成执行、图像模型、文生图 |
| `video_analyze` | 5 | 自适应抽帧、音频事件识别、音频模型状态、抠像、抠像模型状态 |

（`video_scan` 已并入 `video_env {action:"scan"}`；上表由注册结果实测，见 §13.5 与 §15.6。）

### 4.3 `video_env` — 环境与素材

```jsonc
{
  "action": "probe" | "scan" | "presets" | "install_ffmpeg" | "install_ocr",   // required
  "root": "素材目录",                        // scan 用，相对 cwd 解析
  "recursive": true,                         // scan 用，默认 true
  "dedupe": true,                            // scan 用，默认 true
  "source": "rapidocr-json",                 // install_ocr：装哪个引擎（见 §13）
  "archive": "D:/下载/RapidOCR-json_v0.2.0.7z",  // install_ocr：用本地包，不下载（sha256 照样校验）
  "prune": true,                             // install_ocr：删掉用不到的语言库，省约 50MB
  "remove": false                            // install_ocr：改成卸载
}
```

| action | 做什么 | 返回 |
| --- | --- | --- |
| `probe` | 自检：ffmpeg/ffprobe 路径与版本、编解码器与滤镜可用性、Edge TTS 可达性、方舟 Key 是否存在、输入通道、**OCR 引擎是否可用** | `{ok, ffmpeg:{...}, ffprobe:{...}, tts:{...}, ark:{...}, input:{...}, ocr:{available,kind,executable}, problems[]}` |
| `scan` | 枚举素材并探测每个文件 | `{root, counts, images[], videos[], audio[], duplicates[], skipped[], total_duration}` |
| `presets` | 画布预设表 | `{presets: {name: {width,height,fps,label}}}` |
| `install_ffmpeg` | 下载固定版本的 ffmpeg 静态构建到 `vendor/ffmpeg` | `{installed, url, sha256, files, state}` |
| `install_ocr` | 下载（或用 `archive` 本地包）并解包固定版本的离线 OCR 引擎到 `vendor/ocr/<source>`，**sha256 先校验再解包** | `{installed, source, executable, pruned[], state, ocr}` |

**`scan` 的确定性契约**：同一目录、同一参数，返回的 `images[]` 顺序由
`(kind, basename.toLowerCase())` 决定，去重阈值固定，不依赖文件系统枚举顺序。

`scan` 不做任何取舍：不丢重复项（只标 `duplicate_of`），不排序成"建议顺序"，不写计划。
**用哪张、怎么排，是 DSH 的事。**

### 4.4 `video_narrate` — 配音与字幕

```jsonc
{
  "action": "synthesize" | "to_cues" | "srt_write" | "srt_read" | "layout",
  "text": "旁白文本",                  // synthesize: 内联；与 textPath 二选一
  "textPath": "script.txt",            // synthesize: 从文件读（UTF-8，自动去 BOM）
  "outDir": "narration",               // synthesize 输出目录
  "voice": "zh-CN-XiaoxiaoNeural",     // synthesize，默认取配置
  "rate": "+0%", "pitch": "+0Hz", "volume": "+0%",
  "wordsPath": "narration/voiceover.words.json",  // to_cues: 时间戳来源；缺省用上一次 synthesize 的产物
  "maxChars": 18,                      // to_cues / layout：每行最多几个字
  "cuesPath": "narration/voiceover.cues.json",    // srt_write 输入
  "srtPath": "narration/voiceover.srt",           // srt_write 输出 / srt_read 输入
  "scale": 1.05,                       // layout：把整条时间轴按倍数缩放（对齐画面时长用）
  "style": { ... }                     // layout：见下
}
```

| action | 做什么 | 返回 |
| --- | --- | --- |
| `synthesize` | 调 Edge TTS 合成 mp3，同时收集**逐词边界** | `{audio, words, duration, wordCount}` |
| `to_cues` | 逐词时间戳 → 字幕条。**断句规则实测有三条，不只句末标点**：① 词文本以句末标点结尾 ② 词间静音 ≥ `gapBreak`（默认 0.45s）③ 单条累计时长 ≥ `maxDuration`（默认 6s）。③ 与 ② 都对 demo 数据有实际影响（最大静音 0.575s，关掉 ② 会让 9 条变 8 条）。超长按 `maxChars` 折行 | `{cues[], cueCount}`，并落盘 `voiceover.cues.json` |
| `srt_write` | 字幕条 → `.srt` 文件 | `{srt, cueCount}` |
| `srt_read` | `.srt` → 字幕条 | `{cues[]}` |
| `layout` | 字幕条 → 烧录样式与排版参数（尺寸、边距、颜色、描边），**纯计算** | `{style}`，可直接填进 `plan.json` 的 `subtitles` |

**为什么把 `synthesize` 和 `to_cues` 拆开**：TTS 要联网、有成本、可能失败；断句是纯计算、可以反复调。
拆开后 DSH 可以合成一次、试三种断句方式，而不用重新合成。

**拼接提示**：`synthesize` 返回的 `audio` / `words`，`to_cues` 返回的 `cues` 与 `cueCount`，
`layout` 返回的 `style` —— 这几项合起来正好凑出 `plan.json` 的 `audio.voiceover` 与整个 `subtitles` 块。
DSH 拿到后直接填，不需要读文件。

### 4.5 `video_plan` — 计划的确定性部分

```jsonc
{
  "action": "check" | "duration" | "fields" | "diagnose",
  "plan": "plan.json",        // 路径，或（check/duration）直接传内联 JSON 对象
  "planData": { ... },        // 内联计划，与 plan 二选一
  "strict": true              // check：警告也算失败
}
```

| action | 做什么 | 返回 |
| --- | --- | --- |
| `check` | 结构校验 + 路径存在性 + 唯一 id + 取值域，**逐条列出问题** | `{ok, errors[], warnings[], normalized}` |
| `duration` | 精确时间线时长（含转场重叠扣减） | `{estimatedDuration, sceneCount, perScene:[{id,duration,effectiveOverlap}]}` |
| `fields` | 返回打包的 `PLAN-FIELDS.md` 全文（字段速查） | `{text, version}` |
| `diagnose` | 计划 + 素材清单的健康诊断：引用了不存在的文件、静止图没给 motion、转场时长超过镜头一半、竖屏片里混了横图、总时长偏离配音时长 | `{findings[]}` |

**`diagnose` 的定位**：它只报"客观可判定的问题"，不报"品味"。例如
「`scenes[3].motion` 是 `none`，静止图没有运动会显得呆板」是客观事实；
「第 3 个镜头应该放在第 1 个前面」是创作意见，不报。

**边界**：`check` 绝不"修正"计划。它要么通过，要么列出问题。`normalized` 只做补默认值（如省略的 `fit` 补成 `cover`），
不做任何创造性填充。

### 4.6 `video_render` — 渲染

```jsonc
{
  "action": "scene" | "assemble" | "finalize" | "deliver" | "build",
  "plan": "plan.json",              // 或 planData 内联
  "sceneId": "s03",                 // scene：只渲染这一个
  "workDir": "out/.work",           // 默认 <outDir>/.work
  "outDir": "out",                  // 默认 plan.json 同级 output/
  "clips": [".../000_s01.mp4"],     // assemble：缺省用 workDir/scenes/* 按计划顺序
  "timeline": "out/.work/timeline.mp4",  // finalize / deliver 输入
  "quality": "medium",              // 覆盖 plan.meta.quality
  "force": false                    // 忽略缓存重渲染
}
```

| action | 做什么 | 产出 |
| --- | --- | --- |
| `scene` | 渲染**一个**镜头成规格统一的中间片段 | `work/scenes/<NNN>_<id>.mp4` |
| `assemble` | 拼接所有片段（无转场走 concat 流复制，有转场走 xfade） | `work/timeline.mp4` |
| `finalize` | 混音 + 响度归一 + 烧字幕 | `out/final.mp4` |
| `deliver` | 封面帧 + 缩略图总览 + 验收报告 | `cover.jpg` / `contact-sheet.jpg` / `build-report.json` |
| `build` | 上面四步串起来（**仅供 DSH 想让插件代劳整链时使用**） | 全部 |

**为什么 `scene` 要单独暴露**：这是整个渲染里最贵、最需要重试的一步。
它同时是**规格统一算子**——所有画布尺寸、帧率、像素格式、时间基、**以及音轨长度**都在这一步对齐。
只要这一步的契约成立，后面 `assemble` 的 concat 与 `xfade` 就是安全的（见 §5.1）。

**缓存的确定性契约**：`scene` 在片段与旁车指纹都匹配时复用。
- 指纹取 `scenes[i]` 的 `duration/motion/fit/overlays/transition/start/speed/volume/muted/source` 以及画布与帧率，
  连同当前 ffmpeg 版本一起哈希，写进 `<clip>.meta.json`。
- **不用 mtime**：时间戳无法判断"内容变了没有"，会造成 DSH 改了参数却静默复用旧片段的假成功。
- ffmpeg 换版本也要失效——滤镜行为可能随版本变化。
- `force: true` 仍然保留，用于强制忽略指纹全量重渲染。

同样的指纹机制用在 `assemble`（画布 + 顺序 + 转场）和 `finalize`（时间线 + audio/subtitles 块）上，
所以 DSH 只改字幕样式时只有 `finalize` 重跑，改一个镜头时只有那一个镜头重跑。

### 4.7 `video_inspect` — 验收、媒体信息与读图

```jsonc
{
  "action": "verify" | "media" | "ocr" | "find_text" | "ocr_status",
  "plan": "plan.json",          // verify 用
  "target": "out/final.mp4",    // verify / media 用；ocr / find_text：图片或视频
  "paths": ["a.mp4","b.jpg"],   // media：批量；ocr：最多 12 张图
  "needle": "始终安装",          // find_text：要查找的文字，可给数组
  "match": "contains",          // find_text：contains（默认，整行包含）/ exact（整行相等）
  "region": "600,100,620,56",   // ocr / find_text：只读这一块，也可给 {x,y,width,height}
  "scale": "auto",              // ocr / find_text：放大倍数；auto = 小图放大到长边约 1000px
  "engine": "auto",             // auto（离线优先，退回 WinRT）/ local / winrt
  "language": "ch",             // 识别语言，默认简中
  "maxSideLen": 1024,           // 交给引擎的长边上限
  "minScore": 0.5,              // ocr：低于此分数的行不进合并 text，"lines" 里仍然有
  "frames": 4,                  // ocr：视频抽几帧；也可用 "times": [1, 5.5]
  "times": [1, 5.5]
}
```

| action | 做什么 | 返回 |
| --- | --- | --- |
| `verify` | 成片 vs 计划：分辨率、帧率、时长（±6% 或 1s）、有无音轨、像素格式、体积下限 | `{ok, problems[]}` |
| `media` | 任意媒体的流信息 | `{streams:[{width,height,fps,duration,hasAudio,pixFmt,sizeBytes,...}]}` |
| `ocr` | 读图片（或视频抽帧）里的文字：**每行都带像素框、置信度**，并给出合并文本 | `{kind, engine, elapsedMs, lineCount, dropped, text, lines[], frames?[], notes[]}` |
| `find_text` | 在一张图（或视频帧）里找文字，返回每处的框与**中心点**（可直接点） | `{ok, matches[], best, matchCount, searched[], notes[]}` |
| `ocr_status` | 报 OCR 引擎状态，不读任何文件 | `{available, kind, executable, source, vendored, prefer}` |

**`problems` 空数组才算干净交付**——这条要写进 `video_render` 的返回说明里，让 DSH 必须把问题翻译给用户。

**`ocr` 与 `find_text` 的分工**：`ocr` 是"这张图上有什么字"，`find_text` 是"这个字在哪"。
两者都返回完整坐标，区别只在意图：前者读数据，后者定位控件。合并成一件事会让
"我要读出整页文字"和"我要点那个按钮"共用一套含糊的返回结构。

**为什么用 OCR 而不是让模型看图**：模型能读懂图，但**给不出可靠的像素框**；
而"点这个按钮"需要的正是像素。反过来，OCR 读不出画面的含义——
**该看图的场景直接看图，该要坐标的场景用 OCR**，两者不是替代关系（见 §13.4）。

### 4.8 `video_gen` — 字节跳动云生成

```jsonc
{
  "action": "models" | "generate",
  "prompt": "清晨的城市天际线，缓慢推近",   // generate
  "mode": "text-to-video" | "image-to-video" | "first-last-frame",
  "reference": "素材/01.jpg",               // image-to-video：本地图（插件转 data URL）或公网 URL
  "lastFrame": "素材/02.jpg",               // first-last-frame：尾帧
  "referenceImages": ["a.jpg","b.jpg"],     // 1.0 Lite I2V 专用，1–4 张
  "duration": 5,                             // 整数秒（取值域未实证）
  "resolution": "720p",                      // 480p / 720p / 1080p
  "ratio": "16:9",                           // 16:9 / 4:3 / 1:1 / 3:4 / 9:16 / 21:9 / adaptive
  "model": "doubao-seedance-2-0-260128",     // 覆盖默认模型（见 §7.2，勿用已下线的 1-5-pro）
  "seed": -1,                                // -1 = 随机；非 -1 可近似复现
  "generateAudio": false,                    // 未实证
  "draft": false,                            // 未实证
  "serviceTier": "default",                  // default / flex（离线，便宜 50%，更慢）
  "returnLastFrame": false,                  // 返回末帧 URL，供续写
  "cameraFixed": false,
  "watermark": true,                         // 默认 true，履行 AI 内容标识义务
  "outDir": "generated",                     // 落盘目录
  "sceneId": "s07",                          // 落盘文件名 <sceneId>.mp4
  "pollIntervalSeconds": 15, "maxWaitSeconds": 900
}
```

| action | 做什么 | 返回 |
| --- | --- | --- |
| `models` | 列出模型 ID 与各自支持的模式、时长范围、分辨率取值；接上真实 Key 后校验静态表并回报差异 | `{models:[{id, modes, minDurationSeconds, maxDurationSeconds, resolutions, supportsAudio, supportsDraft}], verified}` |
| `generate` | 提交 + 轮询（`ctx.logger` 每轮报进度）+ **成功后立刻下载落盘** | `{jobId, state, localPath, videoUrl, lastFrameUrl, duration, resolvedParams, pollCount, elapsedSeconds}` |

**为什么"提交"和"轮询"合并成一个 action**：结果 URL **24 小时过期**，中途交回 DSH 让它自己轮询，
既拿不到进度也没法保证它记得下载。合并后插件负责到"文件已在本机"为止。
但 `generate` 是长任务（2–5 分钟），必须**边轮询边把状态写进 `ctx.logger`**，否则 DSH 和用户看到的是一片空白。

**确定性说明（必须写进工具描述）**：`video_gen` 是**唯一不满足"同输入同输出"的工具**——
同 prompt 不同结果（`seed` 非 -1 时可近似复现，但不是保证）。它是"执行器"而不是"确定性算子"。
工具描述里要明说，避免 DSH 误以为自己拿到了可复现的产物。

**续写接口**：`returnLastFrame: true` 时返回 `lastFrameUrl`，DSH 把它作为下一段的 `reference` +
`mode: "image-to-video"` 即可拼接长镜头。插件不自动续写——分几段、怎么接是创作决策。

### 4.9 `video_analyze` — 看懂一条已有片子

回答两个此前完全空白的问题：**哪一刻值得看**，和**这是什么声音**。

```jsonc
{
  "action": "sample_frames" | "audio_events" | "audio_status",
  "target": "out/final.mp4",

  // sample_frames
  "strategy": "adaptive",        // adaptive（默认）/ uniform / scene_change / motion_aware
  "probeFps": 4,                 // 解码代理流的帧率，上限 30
  "targetFps": 1,                // 安静段落回落到的节奏
  "minFps": 0.25, "maxFps": 4,   // 保留节奏的下限 / 上限
  "sceneThreshold": 30,          // 判定为"剪切"的平均绝对亮度差（0–255）
  "motionThreshold": 5,          // 判定为"有运动"的同一量纲阈值
  "maxFrames": 2000,
  "extract": false,              // true = 把选中的帧写成 JPEG 并返回路径
  "outDir": "tmp/frames", "maxSide": 640,

  // audio_events
  "start": 0, "duration": 30,    // 只分析一段（长片分段走）
  "topK": 3, "minScore": 0.1,
  "silenceRms": 0.002,           // 低于此 RMS 的窗报 silent，不强行贴标签
  "includeSegments": true
}
```

| action | 做什么 | 返回 |
| --- | --- | --- |
| `sample_frames` | 解码灰度代理流，逐帧与前一帧求平均绝对亮度差，按 `strategy` 选出**值得看的时刻**；每帧都带选中理由与分值 | `{duration, probe:{fps,width,height,decodedFrames}, strategy, thresholds, frames:[{at,reason,sceneScore,motionScore,gapFromPrevious,file?}], skipped, notes}` |
| `audio_events` | 把音轨分类到 AudioSet 521 类，给出**逐窗标签与时间点** | `{path, durationSec, segments:[{at,endAt,rms,silent,labels:[{label,score}]}], events:{标签:[时间点…]}, soundtrack:{windows,classified,silent}, notes}` |
| `audio_status` | 报模型是否装好、多少类、占多少空间，不分析任何文件 | `{available,kind,classes,fileCount,totalBytes,modelBytes,runtimeBytes,model,runtime,installWith?}` |

**为什么这一族要独立成工具**：`video_inspect` 的三个问题是"这条文件是什么规格""上面写了什么字""字在哪"，
都是**对文件本身的核对**；`video_analyze` 问的是"这条片子作为内容是什么样"，是**感知**。两者可以并存但
不该混：把感知动作塞进 `video_inspect` 会让那族从"验收"漂移成"什么都做"。

**每个动作只报测量，不下结论**（与 §2.3 判据一致）：

- `sample_frames` 说"这里有一个剪切，分 46.0"，不说"这个转场用得好"；
- `audio_events` 说"1.92s 起是 Music，置信度 0.98"，不说"配乐选得对"；
- `audio_status` 不分析任何文件，所以它可以在没装模型时安全调用。

**`reason` 是设计的一部分，不是调试信息。** 一帧被选中必须能说出为什么，否则"自适应"就退化成一个
黑箱抽样器，而黑箱抽样器无法审计。合法取值：`first_frame` / `scene_change` / `motion` / `periodic` /
`max_interval_fallback` / `uniform`。

`first_frame` 恒定选中，保证**任何**输入都不会抽成零帧；`max_interval_fallback` 保证长期静止的片子
仍然每隔 `1/minFps` 秒被看一眼。两者合起来是"永不空、永不瞎"的下界。

## 5. 渲染内核设计

### 5.1 四阶段流水线（保留现有设计）

| 阶段 | 做什么 | 产物 | 缓存键 |
| --- | --- | --- | --- |
| **normalize** | 每个镜头统一画布/帧率/像素格式/时间基，且**音轨长度精确等于镜头时长**（无音源填静音） | `work/scenes/NNN_id.mp4` | 该镜头相关字段的指纹（`<clip>.meta.json`） |
| **assemble** | 无转场→concat demuxer 流复制；有转场→单条 `filter_complex` 串 `xfade`/`acrossfade` | `work/timeline.mp4` | 画布 + 镜头顺序 + 全部转场的指纹 |
| **finalize** | 配音 + 音乐混音（`sidechaincompress` 闪避）+ EBU R128 + 字幕烧录，**视频最多重编码一次** | `out/final.mp4` | 时间线指纹 + audio/subtitles 块的指纹 |
| **deliver** | 封面帧、缩略图总览、验收报告 | `cover.jpg` / `contact-sheet.jpg` / `build-report.json` | 每次都重做（便宜） |

### 5.2 滤镜图构造（纯计算，可单测）

Node 侧要 1:1 保留的既有算法：

**颜色换算**
- `#RRGGBB` → ffmpeg 的 `0xRRGGBB`（支持 3 位缩写展开）
- `#RRGGBB` → ASS 的 `&H00BBGGRR`（注意是 BGR 序）

**fit 映射**（源 → 画布宽高）
- `cover`：`scale=W:H:force_original_aspect_ratio=increase,crop=W:H`
- `contain`：`scale=...:decrease,pad=W:H:(ow-iw)/2:(oh-ih)/2:color=black`
- `blur-pad`：`split` → 背景放大+`gblur=sigma=28`+`eq=brightness=-0.10`；前景缩小 → `overlay` 居中
  （需要给分叉加上标以支持同一滤镜图里多个场景，沿用现有 `_{sceneId}` 约定）

**运动映射**（静止图，先 4 倍超采样再 `zoompan`，否则整数像素栅格会有可见抖动）
- 统一：`scale=4W:4H:force_original_aspect_ratio=increase,crop=4W:4H` 前置
- `zoom-in`：`z=1+0.18*on/span`，居中
- `zoom-out`：`z=1.18-0.18*on/span`，居中
- `pan-right`：`z=1.15`，`x=(iw-iw/zoom)*on/span`，垂直居中
- `pan-left`：`z=1.15`，`x=(iw-iw/zoom)*(1-on/span)`，垂直居中
- `kenburns`：`z=1.05+0.15*on/span`，`x` 从 0.5→0.85、`y` 从 0.5→0.20
- `zoompan=d=1` 配合"输入已被 `-t` 限定为镜头时长"的循环图，使每个输入帧恰好产出一个输出帧

**overlay（画面文字）**
- 九宫格锚点 → `x`/`y` 表达式
- `fontsize` 与 `margin` 按 `width/1080` 缩放
- `enable='between(t,start,end)'`
- 可选 `box=1:boxcolor=black@0.45:boxborderw=fontsize/3`
- **文本一律走 `textfile=`，绝不内联**（中文 + BOM + 冒号转义三重坑）

**atempo 链**：`atempo` 单实例只接受约 0.5–2.0，超出范围要拆成多个实例连乘

**转场偏移**（含重叠扣减）
```
有效重叠 = min(转场时长, 本镜时长*0.5, 上一镜时长*0.5)
offset[i] = 已累计时长 - 有效重叠
```

**xfade 前置**：每个输入先 `settb=AVTB,setpts=PTS-STARTPTS`，否则 xfade 时间基不一致

### 5.3 必须保留的 ffmpeg 工程约束

这几条是踩出来的，Node 版必须原样保留（迁移时逐条对拍）：

| # | 约束 | 原因 |
| --- | --- | --- |
| E1 | 所有 ffmpeg 调用**同时**加 `-nostdin` 和 `-y` | 只加 `-nostdin` 时输出已存在会要交互确认，退出码 1 但 stderr 只有一行 `Duration:`，极难查 |
| E2 | 一律**参数数组 + spawn**，绝不拼 shell 字符串 | 中文路径与空格不需要转义，也避免命令注入 |
| E3 | 中间产物路径 > `pathBudget`（200）直接报错 | Windows 260 上限未必开启，超限报错信息极具误导性 |
| E4 | 字体拷贝到 `work/fonts/cjk.ttc` 后按相对路径引用；libass 走 `fontsdir='fonts'` | 本机 ffmpeg 无 fontconfig；同时绕开 `C:` 的冒号被滤镜解析器当选项分隔符 |
| E5 | 字幕文件重编码为**无 BOM** UTF-8 后再交给 libass | BOM 会渲染成杂字符；GBK 会渲染成乱码 |
| E6 | 音频混音一律 `amix=...:normalize=0` | amix 默认把每个输入电平减半 |
| E7 | concat 清单文件用**正斜杠路径**且无 BOM | concat demuxer 的要求 |
| E8 | Edge TTS 必须显式请求 `WordBoundary` | 7.x 默认返回 `SentenceBoundary`，按 Word 过滤会得到空列表，表现为"合成失败"但音频其实已写出 |
| E9 | `-stream_loop -1` 用于短于镜头的视频素材 | 否则会冻在最后一帧 |
| E10 | `apad` + 输出侧 `-t` 用于素材音轨短于画面的情况 | 先补长再裁回精确时长 |
| E11 | 中间片段用 `MEZZANINE_CRF=16`，交付质量由 finalize 一次决定 | 避免多次重编码累积损失 |

### 5.4 编码参数

| 层 | 参数 |
| --- | --- |
| 中间片段 | `libx264 -preset veryfast -crf 16 -pix_fmt yuv420p -color_range tv -profile:v high`，关键帧间隔 `2*fps` 且 `sc_threshold=0`，`-video_track_timescale 90000`，音频 `aac 192k 48000 stereo` |
| 交付（high） | `crf 18 -preset medium`，音频 `192k` |
| 交付（medium） | `crf 21 -preset medium`，音频 `160k` |
| 交付（draft） | `crf 27 -preset veryfast`，音频 `128k` |
| 交付公共 | `yuv420p`、`-color_range tv`、`bt709` 三件套、`-movflags +faststart` |
| 字幕烧录时 | 视频必须重编码（`video_out != 0:v`）；不烧字幕时 `-c:v copy` |
| 软字幕 | 烧录关闭时额外生成 `mov_text` 字幕轨并替换 `final.mp4` |

## 6. `plan.json` 规格（不变）

Schema 保持版本 1，字段与语义完全不变——这是 DSH 与插件之间唯一的契约，改动会同时破坏两边。

**根**：`version`(1) / `meta` / `audio` / `subtitles` / `scenes[]`

**meta**：`title`、`preset`（`vertical-short`|`horizontal`|`square`|`landscape-4k`|`preview`）、
`width`/`height`/`fps`（覆盖 preset）、`quality`（`high`|`medium`|`draft`）

**audio**：`voiceover`、`music`、`music_gain_db`(-60..12, 默认 -18)、`duck`(true)、
`duck_amount`(0..1, 0.18)、`fade_in`(0)、`fade_out`(1.5)、`loudness_target`(-40..-5, -14)、`keep_scene_audio`(true)

**subtitles**：`enabled`、`source`（`.srt`/`.ass` 路径或 `auto`）、`burn`(true)、
`font_size`(44)、`margin_v`(200)、`primary_color`、`outline_color`、`outline`(3)、`bold`、`max_chars_per_line`(18)

**scenes[]**

| 字段 | 取值域 | 默认 |
| --- | --- | --- |
| `id` | 唯一，缺省 `s01`, `s02`… | 自动 |
| `kind` | `image` / `video` / `color` / `generated` | 有 `generate` 时 `generated`，否则 `video` |
| `source` | 相对 `plan.json` 的路径 | — |
| `color` | `#RRGGBB`（`kind=color` 时） | `#000000` |
| `duration` | 0.2–600 秒 | 3.0 |
| `motion` | `none`/`kenburns`/`zoom-in`/`zoom-out`/`pan-left`/`pan-right` | `none` |
| `fit` | `cover` / `contain` / `blur-pad` | `cover` |
| `start` | ≥0 | 0.0 |
| `speed` | 0.1–10 | 1.0 |
| `volume` | 0–4 | 1.0 |
| `muted` | bool | false |
| `transition` | `{type, duration}`；type ∈ `none`/`fade`/`fadeblack`/`fadewhite`/`wipeleft`/`wiperight`/`slideleft`/`slideright`/`smoothleft`/`circleopen`/`dissolve`，duration 0–5 | `{none, 0.5}` |
| `overlays[]` | `{text, anchor, font_size(8–400), color, box, margin(0–2000), start, end}` | 见 §6.1 |
| `generate` | `{provider, mode, prompt, reference, duration, resolution, model, extra}` | — |
| `note` | 任意，不参与渲染 | `""` |

**§6.1 overlay 默认值**：`anchor=bottom-center`、`font_size=48`、`color=#FFFFFF`、`box=true`、`margin=80`、`start=0`、`end=null`

**字段速查文档**：现有 `FIELD_REFERENCE`（`plan.py` 末尾的中文速查表）打包为 `src/assets/PLAN-FIELDS.md`，
由 `video_plan {action:"fields"}` 返回。内容要更新掉所有 Python 说法。

## 7. 云生成：字节跳动火山方舟

> **来源说明与实证状态**：火山方舟官方文档站（`docs.volcengine.com` / `docs.byteplus.com`）是客户端渲染，
> 抓取只得到 HTTP 200 + 空正文，`?mode=markdown` 也无效，**登录并不能解决**（问题在 JS 渲染而非鉴权）。
>
> 初版契约来自两份独立的第三方 GitHub 项目（[doubao-seedance-video-skill](https://github.com/a86582751/doubao-seedance-video-skill/blob/main/references/api-quickref.md)、
> [canghe-skills](https://github.com/freestylefly/canghe-skills/blob/master/skills/seedance-video-generation-1.0.3/SKILL.md)），两者互相印证。
>
> **随后用真实 Key 实证，推翻了其中最关键的一条**：它们推荐的默认模型
> `doubao-seedance-1-5-pro-251215` 在方舟侧**状态是 `Shutdown`（已下线）**，
> 且多个 ID 根本不存在。**下表已按实证结果重写**，第三方结论仅作历史记录保留。
>
> 实证还发现一个第三方资料完全没提到的端点：**`GET /models`**，可列出账号可见的全部模型及其状态。
> 这比任何静态表都可靠，`video_gen {action:"models"}` 必须实现它。

### 7.1 API 契约

**端点**

```
POST   {base}/contents/generations/tasks        创建任务
GET    {base}/contents/generations/tasks/{id}   查询任务
GET    {base}/contents/generations/tasks?page_num=1&page_size=10&filter.status=succeeded   列表
DELETE {base}/contents/generations/tasks/{id}   取消 queued / 删除历史
GET    {base}/models?page_num=1&page_size=100    列出账号可见模型（实证发现，第三方资料未提及）
base = https://ark.cn-beijing.volces.com/api/v3
```

**`GET /models` 是权威来源，必须实现。** 实测返回（分页，HTTP 200）：

```jsonc
{ "data": [ { "id": "doubao-seedance-2-5-260628", "name": "doubao-seedance-2-5",
              "object": "model", "status": "…", "created": 1714982195, "domain": "", "features": {}, "version": "…" } ] }
```

`status` 实测取值与含义（本账号 135 个模型的分布：`Shutdown` 83、`undefined` 35、`Retiring` 17）：

| 观测值 | 含义 | 可用性 |
| --- | --- | --- |
| 字段缺失 / `undefined` | 在售 | ✅ 可用（未开通时创建任务返回 `ModelNotOpen`） |
| `Retiring` | 退役中 | ⚠️ 可能仍可用，不应作为新项目默认 |
| `Shutdown` | 已下线 | ❌ 不可用 |

**鉴权**：`Authorization: Bearer $ARK_API_KEY`，`Content-Type: application/json`

**实测错误码**（用于 `video_gen` 的分类处理）：

| code | HTTP | 含义 | 处理 |
| --- | --- | --- | --- |
| `AuthenticationError` | 401 | Key 缺失或无效 | 直接报错，提示配 `ARK_API_KEY` |
| `InvalidEndpointOrModel.NotFound` | 404 | 模型不存在**或**本账号/本区域不可见 | 提示去 `/models` 核对，或去控制台开通 |
| `ModelNotOpen` | 404 | 模型存在但**账号未开通** | 提示"请在方舟控制台激活该模型" |
| `InvalidParameter` | 400 | 参数越界（如时长） | 直接报错并回显合法取值域 |

> 实测确认：**模型校验先于参数校验**。传 `duration: 1`（非法）时，报的是模型错误而非时长错误——
> 这个顺序让"用非法参数探测模型是否存在"成为可行手段，也是本次实证能免费完成的原因。


**创建请求体**——关键结论：**`ratio`/`resolution`/`duration`/`watermark` 等是独立 JSON 字段，
不是拼在 prompt 后面的 `--resolution` 后缀**（§7.3 Q4 已解决）。

```jsonc
{
  "model": "doubao-seedance-2-0-260128",
  "content": [
    { "type": "text", "text": "清晨的城市天际线，缓慢推近" },
    { "type": "image_url", "image_url": { "url": "https://… 或 data:image/png;base64,…" }, "role": "first_frame" }
  ],
  "ratio": "16:9",              // 16:9 / 4:3 / 1:1 / 3:4 / 9:16 / 21:9 / adaptive
  "duration": 5,                // 整数秒
  "resolution": "720p",         // 480p / 720p / 1080p
  "seed": -1,                   // -1 = 随机
  "camera_fixed": false,
  "watermark": false,
  "generate_audio": false,      // 未实证
  "draft": false,               // 未实证
  "return_last_frame": false,   // 返回末帧 URL，用于续写
  "service_tier": "default",    // default（在线）/ flex（离线，便宜 50%，更慢）
  "execution_expires_after": 172800   // 3600–259200
}
```

`content[].role` 取值：`first_frame`、`last_frame`、`reference_image`（**均未实证**）。

**查询响应**

```jsonc
{
  "id": "cgt-…",
  "model": "doubao-seedance-2-0-260128",
  "status": "succeeded",                    // queued / running / succeeded / failed / expired
  "content": { "video_url": "https://…", "last_frame_url": "https://…" },
  "error": { "message": "…" },              // status=failed 时
  "usage": { "completion_tokens": 216900, "total_tokens": 216900 },
  "resolution": "720p", "ratio": "16:9", "duration": 10, "framespersecond": 24
}
```

**结果 URL 有效期 24 小时；任务历史保留 7 天**（均未实证，按此实现）。

**图片要求**（未实证）：jpeg/png/webp/bmp/tiff/gif；
宽高比 0.4–2.5；每边 300–6000 px；单文件 ≤ 30 MB。本地图转 base64 data URL 即可。

### 7.2 模型（已实证）

`GET /models` 实测返回的 Seedance 全系列（本账号 2026-10-02 视角）：

| Model ID | 状态 | 可用性 | 备注 |
| --- | --- | --- | --- |
| `doubao-seedance-2-5-260628` | 在售 | 需开通 | 最新世代 |
| `doubao-seedance-2-0-260128` | 在售 | 需开通（实测 `ModelNotOpen`） | 2.0 标准版 |
| `doubao-seedance-2-0-fast-260128` | 在售 | 需开通 | 2.0 快速版 |
| `doubao-seedance-2-0-mini-260615` | 在售 | 需开通 | 2.0 轻量版 |
| `doubao-seedance-1-0-pro-fast-251015` | 在售 | 需开通 | 1.0 快速版 |
| `doubao-seedance-1-0-pro-250528` | `Retiring` | ⚠️ 退役中 | |
| `doubao-seedance-1-0-lite-t2v-250428` | `Retiring` | ⚠️ 退役中 | |
| `doubao-seedance-1-0-lite-i2v-250428` | `Retiring` | ⚠️ 退役中 | |
| `doubao-seedance-1-5-pro-251215` | **`Shutdown`** | ❌ **已下线** | 第三方来源推荐的"默认"，实为不可用 |
| `doubao-seedance-1-0-pro-250428` | 不在列表 | ❌ 不存在 | 第三方来源记错了日期后缀 |
| `doubao-seedance-1-0-lite-t2v-250219` | 不在列表 | ❌ 不存在 | 同上 |
| `doubao-seedance-1-0-lite-i2v-250219` | 不在列表 | ❌ 不存在 | 同上 |

**结论：不要硬编码任何模型 ID 作为唯一默认值。** 正确做法：
1. `video_gen {action:"models"}` 调 `GET /models`，过滤 `id` 含 `seedance`，按 `status` 分成"在售 / 退役中 / 已下线"三档返回。
2. 出厂配置 `ark.defaultModel` 保留，但**首次调用若报 `ModelNotOpen`，插件必须明确回报"该模型需在方舟控制台激活"**，而不是抛一个裸 404。
3. 用户显式传 `model` 时以用户为准。

⚠️ **当前账号状态：没有任何 Seedance 模型处于已开通状态。** 上面"在售"的 5 个都返回 `ModelNotOpen`。
**`video_gen` 端到端跑通的前提是用户先在方舟控制台激活至少一个模型**（见 §11 第 5 条）。

**请求体参数**（**已实证**，模型 `doubao-seedance-2-0-260128` / `-fast` / `-mini` 的 t2v 与 i2v）：

| 参数 | 实证结论 |
| --- | --- |
| `duration` | **4–15 秒**（1/2/3 与 16/30 均拒）。下限 4，上限 15 |
| `resolution` | `480p` / `720p` / `1080p` / **`4k`** 全部接受 |
| `ratio` | `16:9` / `9:16` / `1:1` / `4:3` / `3:4` / `21:9` / `adaptive` 全部接受 |
| `seed` | 接受；响应回显实际使用的 `seed` |
| `watermark` | 接受 |
| `camera_fixed` | 接受 |
| `return_last_frame` | 接受（但**响应默认不含** `content.last_frame_url`，见下） |
| `generate_audio` | 接受 |
| `draft` | 接受 |
| **`service_tier`** | ⚠️ **2.0 / 2.0-fast / 2.0-mini 全部不支持**（报错 "must be empty"）；2.5 支持但**拒绝 `flex`**；**只有 `doubao-seedance-1-0-pro-fast-251015` 接受 `flex`** |
| `content[].role` | `first_frame` / `last_frame` 接受；**不带 `role` 也接受** |

**参数支持按「模型 + 模式」分别限定**，报错措辞为 `... is not supported for model X in t2v, must be empty`。
这条第三方资料完全没提，必须按模型分别处理，不能一套参数用到底。

**实测响应结构**（`doubao-seedance-2-0-fast-260128`，4s/480p，耗时 87 秒）：

```jsonc
{
  "id": "cgt-20261002211025-8s6hl",
  "model": "doubao-seedance-2-0-fast-260128",
  "status": "succeeded",
  "content": { "video_url": "https://ark-acg-cn-beijing.tos-cn-beijing.volces.com/….mp4?X-Tos-…" },
  "usage": { "completion_tokens": 40594, "total_tokens": 40594 },
  "created_at": 1790946625, "updated_at": 1790946711,
  "seed": 78652,                    // 回显实际 seed
  "resolution": "480p", "ratio": "16:9", "duration": 4,
  "framespersecond": 24,            // 注意字段名是 framespersecond，不是 fps
  "service_tier": "default", "execution_expires_after": 172800,
  "generate_audio": true,           // 未显式请求也回显 true
  "draft": false, "priority": 0, "output_format": "mp4"
}
```

**实测要点**：
- 状态机实测只观察到 `running -> succeeded`（未观察到 `queued`），约 87 秒完成一条 4 秒片。
- **TOS 预签名 URL 带 `X-Tos-Expires=86400`，即 24 小时**——与第三方说法一致，**必须立刻下载**。
- `content.last_frame_url` 在未请求 `return_last_frame` 时**不存在**（不要假设它总在）。
- 下载成功：`video/mp4`，944851 字节；`ffprobe` 读出 `864x496 h264 24fps`、时长 4.096s、**含 aac 音轨**。
- **`duration` 是请求值，实际成片时长会有零点几秒偏差**（请求 4s，实测 4.096s）——校验时不能用严格相等。

**图片要求**（未实证）与 **`service_tier` 取值域**（未实证）仍需补。

**默认参数建议**：`720p`、文生 `16:9` / 图生 `adaptive`、`5` 秒。**不要默认传 `service_tier`**（2.0 会直接报错），
也不要默认指望 `return_last_frame` 或 `generate_audio`。

**已实证**（用真实 Key 实测）：

| 项 | 结论 |
| --- | --- |
| 鉴权 | `Authorization: Bearer $ARK_API_KEY` 有效；无 Key 返回 401 `AuthenticationError` |

### 7.4 适配器设计

```
core/ark.mjs
├── listModels()                       GET /models 分页拉全量 → 过滤 seedance → 按 status 分档
├── submit(spec)   → { jobId }         POST /contents/generations/tasks
├── poll(jobId)    → { state, videoUrl, lastFrameUrl, error }
└── generate(spec, { onProgress })     submit → 轮询 → 成功后立刻下载落盘
```

**必须遵守的五条**：
1. **结果 URL 24 小时过期，必须在首次轮询成功后立刻下载落盘**，绝不只把 URL 交给 DSH。
2. **base URL 是配置项而非常量**（区域/工作区差异）。
3. **AI 生成内容有标识义务**（《人工智能生成合成内容标识办法》，2025-09-01 施行，显式+隐式标识且禁止遮挡）。
   默认 `watermark: true`；显式传 `false` 时要在返回里提醒 DSH 自行处理标识。
4. **轮询必须往 `ctx.logger` 报进度**（每 15s 一条），否则 DSH 和用户面对 2–5 分钟空白。
5. **`ModelNotOpen` 必须翻译成人话**：不能把裸 404 抛给 DSH，要回报
   "模型 X 存在但本账号未开通，请到方舟控制台激活"。这是本账号当前唯一会撞到的错误。

**`listModels` 是权威路径**：不要在插件里硬编码任何"可用模型"结论。
每次 `action:"models"` 都实拉 `GET /models`，这样模型上下线、账号开通状态都自动跟随。

**续写（长镜头拆段）**：`return_last_frame: true` → 取 `content.last_frame_url` 作为下一段的 `first_frame`。
DSH 决定要不要续写，插件只提供 `returnLastFrame` 开关和 `lastFrameUrl` 返回。（此机制未实证。）

**`service_tier: "flex"`**：离线队列，便宜 50%、更慢（未实证）。适合草稿阶段。
这条要写进工具描述，否则 DSH 不知道有这个省钱档。

### 7.5 图像生成（Seedream）—— 另一条端点，契约不同

**已实证**。它与视频端点在三处根本不同，不是同一个适配器能覆盖的：

| 项 | 视频 | 图像 |
| --- | --- | --- |
| 端点 | `POST /contents/generations/tasks` | `POST /images/generations` |
| 形态 | **异步**：提交 → 轮询 → 下载 | **同步**：一次请求直接拿结果 |
| 响应 | `content.video_url` | `data[0] = { url, size, output_format }` |

**实测响应**（`doubao-seedream-5-0-flash-260915`，`size: "2k"`，12.1 秒）：

```jsonc
{
  "model": "doubao-seedream-5-0-flash-260915",
  "created": 1790997736,
  "data": [{ "url": "https://ark-acg-cn-beijing.tos-cn-beijing.volces.com/…", "size": "2496x1664", "output_format": "jpeg" }],
  "usage": { "input_images": 0, "generated_images": 1, "output_tokens": 16224, "total_tokens": 16224 }
}
```

- `X-Tos-Expires: 86400`（24 小时）——**与视频一样必须立刻下载**
- 实际输出是 **JPEG**，即使 `size` 写 `2k`；所以落盘扩展名必须跟随 `output_format`
  而不是调用方给的名字（调用方写 `cover.png` 会落成 `cover.jpg`）

**实测参数**：

| 参数 | 结论 |
| --- | --- |
| `size` | 预设 `1k` / `2K` 接受；`WxH` 接受；`4k` 被拒 |
| **面积下限** | **921,600 像素**（`512x512` 报 "image area must be at least 921600 pixels"） |
| **面积上限** | **4,622,220 像素**（`8192x8192` 报 "at most 4624220 pixels"） |
| `guidance_scale` | **5-0-flash 不支持** |
| `sequential_image_generation` | **5-0-flash 不支持** |

**越界在本地先拒**：服务端只说"不合法"而不给范围，所以上下限写成客户端校验，
让错误在花钱之前出现。

**模型在售情况**（同 §7.2 的方法，`filter:'seedream'`）：`3-0-t2i-250415` 与
`seededit-3-0-i2i-250628` 是 `Shutdown`；`4-0-250828` / `4-5-251128` / `5-0-260128` 是 `Retiring`；
在售的是 `5-0-flash-260915` / `5-0-pro-260628` / `4-0-20260415`。

> **成本教训（写给未来的自己）**：第一次"无害探针"用非法 `size` 做参数隔离，以为会被拒。
> 结果 `1k`/`2k`/`1024x1024` 等都是**合法**值，那次探针真的生成并计费了约十张图。
> **图像端点没有"免费试参数"这回事**——`model` + `prompt` 齐备的请求就可能出图并计费。
> 参数探测只能靠**确定非法**的取值，或者干脆不探。

### 12.1 本次冒烟验证的教训（值得写进实现约定）

调试 Edge TTS 时，一个**自己写出来的帧编码 bug** 连续伪装成四种"外部原因"：
403、permessage-deflate 协商失败、服务端建连限流、时钟偏移。逐个排除用了十几轮往返，
最后靠**一个离线纯函数测试**（`encodeFrame` → 解码器 round-trip）一击定位。

具体两个 bug：mask key 写在 `header.length - 4`（2 字节头时越界，4 字节头时**覆盖 FIN/opcode**）；
以及 7/16/64 位长度分支**漏了 MASK 位 `0x80`**——未掩码的客户端帧是协议违规，服务端重置完全合理。

**约定**：凡是能用纯函数离线验证的（帧编码、滤镜串、SRT 断句、计划校验），
**先在本地测到全绿再去打真实服务**。不要用"打真实服务看报错"当第一手段——
第三个未知变量（网络/限流/服务端行为）会让定位成本翻十倍。

## 13. 离线 OCR：选型、实测与坐标规则

### 13.1 为什么需要它

Windows 自带 `Windows.Media.Ocr`（`src/bin/ocr.ps1` 包装）零安装、全屏约 200 ms，
但它**读不准小字和中英混排**。在真实截图上实测（`tmp/click-text.png`，1200x1013，本项目自己的窗口）：

| 真值 | WinRT 读成 |
| --- | --- |
| `TypeScript 编译为 Wasm` | `TvpeScript 编译为 Wasm` |
| `自动化任务` | `自 动 化 亻 壬 务` |
| `deepseek` | `deepseel<` |
| `执行了命令` | `执 彳 亍 了 命 令` |

作为"找个按钮"够用，作为"读数据"不够。所以：**WinRT 保留为零安装兜底，真正干活的是装进 `vendor/ocr/` 的引擎。**

### 13.2 两个引擎，同一套协议

两个引擎都是"常驻子进程 + stdin 一行 JSON 进、stdout 一行 JSON 出"，所以**一套客户端说两家话**：

| 来源 id | 运行时 / 模型 | 许可 | 实测（同一张 1200x1013 截图，本机） |
| --- | --- | --- | --- |
| `rapidocr-json`（默认） | ONNX Runtime + PP-OCRv4 简中 | MIT | 初始化 0.33 s；**1.77 s**；平均置信度 0.929；解包约 95 MB（`prune` 后 44 MB）；不要求 AVX |
| `paddleocr-ppocrv5` | Paddle Inference + PP-OCRv5 mobile | 构建者未声明；模型来自 PaddleOCR（Apache-2.0） | 初始化 0.42 s；**15.9 s**；平均置信度 0.833；要求 AVX；**第三方构建** |

**默认选 ONNX 那个**，理由是可测的：同一张图上它快 9 倍、平均分更高，而且体积小得多。
PP-OCRv5 确实在个别小字上更准（`gap` 没被读成 `qap`），但 15.9 s/张在这个用途上不可接受，
所以它作为可选项保留，而不是默认。

**下载与解包**：包是 `.7z`，而 Windows 不装 7-Zip 就**没有任何工具能解 LZMA**
（本机 `tar.exe` 直接报 `LZMA codec is unsupported`）。因此安装器会顺带取一个 0.6 MB 的官方
`7zr.exe` 放进 `vendor/ocr/tools/`。引擎包按 **sha256 硬校验**后再解包；`7zr.exe` 的官方地址
永远指向最新版，所以它的哈希**只记录不强制**——上游发版就把安装卡死，是比"哈希变了"更糟的失败。

**网络慢时的出口**：`install_ocr {archive:"D:/…7z"}` 用本地包，sha256 照样校验。
这条是实测逼出来的：开发期间 GitHub 的 release CDN 把这次下载限到约 20 KB/s，70 MB 要一小时。

### 13.3 坐标规则（最容易错的地方）

引擎报的是**四点框**（左上/右上/右下/左下）。插件把它降成轴对齐矩形，并且
**永远换算回调用方那张图的坐标系**：

- 给了 `region` → 先 `crop`，框要加回 `region` 的偏移；
- 给了 `scale`（或 `auto`）→ 引擎读的是放大图，框要**除以**倍数；
- 先除后加，顺序反了就是平方级偏移——`ocr.ps1` 里那个注释记的就是这个坑，它当时让点击落到别处，
  看起来像"输入注入失败"。

**小字要先放大**：RapidOCR 官方配置里对小图用 `limit_type: min` + `limit_side_len: 736`，
即把小图短边放大到 736 再识别。这里对应 `scale: "auto"` —— 小图（或小 `region` 裁片）
长边放大到约 1000px，最多 3 倍。实测：整屏 1200x1013 直接读 **2.2 s / 35 行**；
只截 `600,100,620,56` 那块再放大 1.61 倍，**203 ms** 就读出了同一行，而且更干净。

### 13.4 与"让 DSH 自己看图"的边界

云端视觉模型**不提供逐行文字的版面级像素框**（能框出"你描述的那个目标"，不是"每行字都在哪"），
所以：

- 要**含义**（这张图讲的什么、该配什么文案）→ DSH 直接看图，插件不掺和；
- 要**文字与坐标**（读数、找控件、点按钮）→ `video_inspect {action:"ocr"|"find_text"}`。

云端那一路**不实现**，这正是本条边界的结果：既拿不到坐标，又要联网和付费。

## 14. 自适应抽帧：为什么是差分，以及为什么必须报理由

### 14.1 为什么需要它

均匀抽帧有两个结构性缺陷，和实现好坏无关：

1. **预算错配**。一条 3 分钟的片子按固定间隔抽 20 帧，会均匀地浪费在静止的画外音段落上，同时在真正的
   剪辑点附近抽不到东西——而剪辑点恰恰是唯一需要看的地方。
2. **漏掉短事件**。一次 0.3 秒的闪白或跳切，在 2 秒间隔下抽中的概率是 15%。

### 14.2 选型：像素差分，不是模型

| 方案 | 成本 | 本机可行性 | 结论 |
| --- | --- | --- | --- |
| **灰度帧平均绝对差**（选中） | 0 | ✅ ffmpeg 自带 `rawvideo`，无需新依赖 | **采用** |
| 直方图差 / 感知哈希 | 0 | ✅ 已有 `differenceHash`（用于静态图去重） | 不作主信号：丢空间信息，对平移不敏感 |
| 光流（Farnebäck / RAFT） | 中–高 | ⚠️ 需要 OpenCV 或 torch | 不采用：收益不足以换来一个几百 MB 的依赖 |
| 云端视觉模型逐帧判断 | 高 | ✅ 但要 Key + 联网 + 按量付费 | **留给 DSH 看图**，不写进工具 |

差分法的定位要说清楚：它**测量"变了多少"，不测量"变好没有"**。这正是它能进这个插件的原因——
它是确定性算子，而"这个运镜舒不舒服"永远归 DSH（§2.3）。

### 14.3 实测参数与阈值

| 参数 | 默认 | 依据 |
| --- | --- | --- |
| `probeFps` | 4 | 0.25 秒的时间分辨率，够抓住一次跳切；解码开销约为原片的 1/6 |
| `probeWidth × probeHeight` | 160×90 | 决策不需要细节。整片代理流按此几何约 1.4 MB/分钟 |
| `sceneThreshold` | 30 | 硬切的标准差量级；实测红→蓝纯色切换为 **46.0**，远高于噪声 |
| `motionThreshold` | 5 | 低于此值基本是压缩噪声与渐变的残差 |
| `targetFps` | 1 | 安静段落一秒看一眼 |
| `minFps` | 0.25 | 兜底：**最长 4 秒必看一眼** |
| `maxFps` | 4 | 上限等于 `probeFps`，即"再激烈也不会每帧都留" |
| `maxFrames` | 2000 | 硬上限，防止长片把结果撑爆 |

**阈值只在同一几何下可比**，这是这个方法最容易误用的地方：分值是 0–255 的平均绝对亮度差，
改 `probeFps` 会改变相邻帧的时间间隔，改探测分辨率会改变空间平均。所以每次返回都回显
`probe` 与 `thresholds` 实际值，而不是让调用方以为默认值一直有效。

### 14.4 决策顺序（照抄参考实现的语义）

对每个候选帧，按顺序判断，第一个命中即选中：

```
第一帧                        → first_frame（恒选中，永不空）
gap >= maxInterval            → max_interval_fallback（兜底，永不瞎）
────────────────────────────── 策略分支
uniform                       → gap >= targetInterval ? uniform
scene_change                  → score>=sceneThreshold ? scene_change : (gap>=targetInterval ? periodic)
motion_aware                  → score>=motionThreshold ? motion : (gap>=targetInterval ? periodic)
adaptive                      → scene_change / motion / periodic 依次判断
```

`gap < minInterval` 直接跳过，这是 `maxFps` 生效的位置。

### 14.5 为什么每帧都要带 `reason`

因为**不可审计的自适应等于随机**。只返回一串时间点，调用方无法判断"这 25 帧是抓到了精华，还是
阈值设错了导致乱抓"。带上 `reason` + `sceneScore` 之后，参数该怎么调是**可推断的**：

- 全是 `periodic` → 阈值太高或片子确实很静，该调低 `sceneThreshold`；
- 全是 `motion` 没有 `scene_change` → 片子是长镜头或手持，没有硬切；
- 出现 `max_interval_fallback` → 该段落长时间静止，是真的没内容。

### 14.6 与"让 DSH 自己看图"的边界

这一节和 §13.4 是同一条原则的两次应用：

- 分值负责**哪里要紧**（"第 3.67 秒有一次运动，分 16.0"）→ 插件负责，因为它是确定性的；
- 眼睛负责**画面好不好**（"这个构图能当封面吗"）→ DSH 负责，因为它需要判断。

`extract: true` 就是把这两者接起来：插件把选中的帧写成 JPEG 并返回路径，DSH 逐张 `read_image`。
**插件不替 DSH 决定看哪几张**——它给出全部选中的帧，`maxSide` 只控制分辨率不控制数量（超过 60 张才截断）。

### 14.7 验证

- `tests/sampling.test.mjs`（15 例）：`meanAbsoluteDifference` 的算术与长度校验；`scoreFrames` 给首帧
  **null 而不是伪造零分**；参数范围与上限拒绝；`first_frame` 恒选中；静止片不塌缩成空；
  `maxInterval` 兜底位点；`adaptive` 抓到 `uniform` 会错过的剪切点；`scene_change` 与 `motion_aware`
  在同一组分值上给出不同结论；`maxFrames` 生效；保留节奏不超 `maxFps`；每个 `reason` 合法且 gap 为正。
- 解码半程用**现渲染的视频**验证（ffmpeg 参数顺序、raw `gray` 分帧、stdout buffer 路径），
  以及"不是视频"时的可读报错。

## 15. 音频事件检测：选型、实测与来源风险

### 15.1 为什么需要它

转录只覆盖**语音**。而剪辑决策大量依赖非语音信息：音乐什么时候起、哪里是环境噪音、哪一段其实是静音。
在引入本节之前，插件对这些**一无所知**——只能读 ffprobe 的数值。

### 15.2 选型：为什么是 WASM + YAMNet

参考实现（`ai-powered-video-analyzer`）用 **PANNs CNN14**（PyTorch）。同一套 AudioSet 本体，但它带来
Python + torch 依赖，与本插件"纯 ESM、零依赖"的性质冲突。逐条比较后：

| 方案 | 体积 | 结论 |
| --- | --- | --- |
| PANNs CNN14（PyTorch） | torch + 权重 ≈ 数百 MB，且需 Python | ✗ 与 §3.2 的包布局冲突 |
| **YAMNet + `onnxruntime-web`（WASM）** | **28.40 MB** | **✓ 采用** |
| YAMNet + `onnxruntime-node`（原生） | 245.7 MB（三平台 × 两架构） | ✗ 见下 |
| 纯 ffmpeg 信号分析（`silencedetect`/`astats`） | 0 | 只作辅助：能知"有没有声"，不知"是什么声" |

**原生绑定为什么被否掉**：`onnxruntime-node@1.23.0` 的 tarball 解包 **245.7 MB**，因为 `bin/napi-v6/`
下同时带着 darwin/linux/win32 × arm64/x64 的 `libonnxruntime`。即便裁到 win32-x64 单平台也有约 40 MB，
且引入平台二进制与安装步骤。而 WASM 只要两个文件。

**两条路径的一致性已实测**：同一个 440 Hz / 1 kHz 窗，原生得 **0.977062**，WASM 得 **0.977061**。
差值在第 6 位小数，说明 WASM 不是近似实现。既然结果一致，就选小的。

### 15.3 实测数据

| 指标 | 实测值 |
| --- | --- |
| 模型 | `yamnet.onnx` 15.39 MB + 类别表 14 KB |
| 运行时 | `ort-wasm-simd-threaded.wasm` 10.69 MB + `ort.wasm.mjs` 2.43 MB + 四个依赖包 ≈ 13.01 MB || 合计 | **28.40 MB**（128 个文件，逐文件 sha256 校验 0 不匹配） |
| 会话创建 | 287–316 ms（首次，含 WASM 实例化） |
| 单窗推理 | **68–81 ms**（单线程 WASM，CPU） |
| 实测吞吐 | 18.5 秒 / 37 窗 ≈ **709 ms**；10 秒 / 19 窗 ≈ 795 ms |
| 时间预算 | 窗长 0.96 s、跳步 0.48 s → 每步 480 ms 预算，用掉不到两成 |
| 真实素材判定 | demo 成片 18.5 秒 37 窗全部落 **`Music`**（与实际有 BGM 相符） |

### 15.4 模型几何与标签规则

- **输入**：float32 单声道 16 kHz，窗口 **15360** 采样（0.96 s），跳步 **7680**（0.48 s）。
- **ONNX 输入是一维** `[15360]`，不是 `[1,15360]`。传二维会被 ORT 拒绝：
  `Invalid rank for input: waveform Got: 2 Expected: 1`。
- **输出是 `[N,521]` 二维**，按行取平均后再排序。直接读 `data` 而不按行归约，会得到"全零 + Silence"
  这种看似合理实则错误的结果。
- **类别表对齐是这一节最危险的地方**：`yamnet_class_map.csv` 首行是表头，所以**类 N = 数据第 N 行 =
  `lines[N+1]`**（等价于 `lines.slice(1)[N]`）。错一位会让所有标签整体平移且依然"像真的"。
  `tests/audio.test.mjs` 用六个锚点钉住它：`0=Speech`、`382=Alarm`、`383=Telephone`、`387=Dial tone`、
  `388=Busy signal`、`495=Sine wave`、`520=Field recording`。
- **静音不贴标签**：RMS < `silenceRms`（默认 0.002）的窗报 `silent: true`、`labels: []`。让模型对
  数字静音强行给一个类，是产生幻觉标签的主要途径。

### 15.5 来源风险（必须如实声明）

权重来源**不是官方发布**，链路是：

```
Google YAMNet（Apache-2.0，TF-Hub）
  → jafet21/yamnetonnx（个人转存，ONNX 导出）
  → niobures/YAMNet（个人转存；取其 yamnetonnx/ 子目录）
```

因此：

- 许可证标为 **Apache-2.0**，但**没有官方发布的权重哈希可比对**；
- `vendor/audio/SOURCE.json` 里记录的 sha256 是**首次落盘时的完整性锚点**，
  用于**防篡改与复现**，**不构成来源合法性证明**；
- 与 OCR 引擎（有官方 release + sha256）和 ffmpeg（官方发布）**不是同一个信任等级**，
  这一点写进清单而不是含糊带过。商用前建议自行复核。

### 15.6 验证

- `tests/audio.test.mjs`（11 例，不需要模型）：类别表 521 项与六个对齐锚点；表头不对时**拒绝解析而不是
  误读**；WAV 往返解码；**拒绝非 16 位单声道而不是强行转换**；窗口切分与时间点；拒绝非 16 kHz；
  RMS 区分静音与满幅方波；`topLabels` 的多行归约；`minScore` 过滤后仍报 peak；`groupEvents` 分组。
- `tests/audio-engine.test.mjs`（**没有模型时自动跳过**，2 例）：ffmpeg 现渲染"静音 + 双音 + 静音"，
  断言音调段被分类且标签全部解析成真实名称（`/^#\d+$/` 视为失败）；**开头的数字静音被报为 silent
  而不是被贴标签**；相邻段的时间差精确等于跳步 0.48 s；无音轨的视频给出"可能没有音轨"的可读报错。

  环境自检：`node src/bin/vf.mjs doctor`（含 `audio` 段）。

### 15.7 失败语义（实测）

安装音频模型时经历了两次真实的 `fetch failed`，结果证明失败是**安全的**：

| 时刻 | 事件 | 结果 |
| --- | --- | --- |
| 第 1 次 | 下载 `yamnet.onnx` 超时 | `verifyInstalledAudio()` 仍报 **128/128 全绿**、0 不匹配 |
| 第 2 次 | 同上 | 同样全绿 |

原因是顺序设计：文件先落到 `.download/`，**在那里算 sha256**，只有匹配才 `writeFileSync` 到正式位置，
`finally` 里无论成败都删掉临时文件。所以"下载中断"和"树被破坏"之间没有通路。这条要有测试守住它的
前提——`install_audio` 会在下载**之前**先验证 pinned 哈希本身是 64 位小写十六进制，否则直接拒绝：
一个写错的 pin 若被静默跳过比较，就等于安装了一个未经校验的模型。

### 15.8 系统代理：Node 与 Windows 的落差

这是本次实现中最难查的一个问题，值得单独记下。

**现象**：`install_audio` 在 Node 里连续两次报 `fetch failed`，而同一个 URL 用
`Invoke-WebRequest` **1.4 秒**就取到了。

**根因**（逐层实测排除）：

1. 并非网络不通——Node 访问 `registry.npmjs.org` 与 `example.com` 都正常，**只有 HuggingFace 直连超时**；
2. `error.cause` 是 `UND_ERR_CONNECT_TIMEOUT`，卡在 `104.244.43.248`，即 HF 的 LFS CDN 节点；
3. 本机 **Windows 系统代理已启用**：`ProxyEnable=1`、`ProxyServer=127.0.0.1:7897`（注册表
   `HKCU\...\Internet Settings`）；`CONNECT` 隧道实测返回 200；
4. **Node 的 `fetch` 不读注册表代理**，而 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量为空；
5. 手动设上这两个变量、并加 `NODE_USE_ENV_PROXY=1`，**Node 24 仍然直连超时**——所以环境变量路线
   在这个版本上不成立。

**做法**：`src/core/install.mjs` 自己解析代理（环境变量优先，其次注册表），实现
`httpFetch()`：`http CONNECT` 建隧道 → `tls.connect({ socket, servername })` 完成握手（**直接把裸
socket 交给 `https.request` 会得到一句没有信息量的 `socket hang up`**）→ `https.request` 走该 socket。
Node 24 **没有可导入的 `undici`**（`import('undici')` 报 `ERR_MODULE_NOT_FOUND`，`node:undici` 报
`ERR_UNKNOWN_BUILTIN_MODULE`），所以只能用内置模块手写。

**顺带修掉的一个静默回归**：自写的 `httpFetch` 第一版不跟随重定向，而 HF 的 `/resolve/` 会 **307/302**
跳到 CDN，于是"下载到的模型"其实是 278 字节的重定向页面。`fetch` 默认跟随重定向，所以改用自写实现时
这一点被无声丢掉——**是后续的字节数与 sha256 校验把它暴露出来的**。这说明哈希校验不只是防篡改，
也是这类静默退化的探测器。

**影响面**：`download()` 是 `install_ffmpeg`、`install_ocr`、`install_audio` 共用的入口，所以这一个修复
同时解决了三个安装动作在代理环境下的可用性。

## 16. 抠像：两条路径与它们的分界

### 16.1 为什么分成两条

把主体从背景里分离出来有两种做法，成本差着三个数量级，混为一谈就会用错工具：

| 路径 | 成本 | 何时正确 |
| --- | --- | --- |
| **`colorkey`（纯色背景）** | 约等于解码时间，零模型 | 绿幕、纯色背板。**精确**，因为是确定性颜色判定 |
| **U²-Net（任意背景）** | 实测约 2.1 秒/帧 | 背景是照片、实景、运动镜头 |

所以 plan 里是两个字段而不是一个带 `mode` 的字段：`chroma_key` 与 `matte`。它们互斥，
同时配置会**直接报错**——两者都是"把主体从背景分离"，同时给会先抠一次再抠一次。

**先问素材形态，再问模型。** 如果背景是纯色，AI 抠像整个是多余的。这是这条分界最重要的推论。

### 16.2 模型选型

| 候选 | 体积 | 结论 |
| --- | --- | --- |
| **u2netp** | **4.36 MB** | **采用** |
| u2net（完整） | 167.84 MB | 不用：38 倍体积换更好的边缘，而边缘可以靠羽化补 |
| ORMBG 量化版 | 42.26 MB | 不用：10 倍体积 |
| BEN2 | 199–209 MB | 不用 |
| SAM / MobileSAM | 需要提示点，不是自动显著性 | 不适用 |

**u2netp 的输入是固定 320x320**，不是动态轴：用 `freeDimensionOverrides` 指定 160 或 224 会被
ORT 直接拒绝（`Got invalid dimensions`）。所以降分辨率这条路走不通，遮罩只能放大回原尺寸，
边缘质量靠 `feather` 而不是靠模型精度。

**输出有 7 个 `[1,1,320,320]`，首位是融合预测。** 另外 6 个是训练用的侧输出。取错输出不会报错，
只会得到一个更差的遮罩。

### 16.3 实测与硬件上限

| 指标 | 实测值 |
| --- | --- |
| 模型 | `u2netp.onnx` 4.36 MB |
| 运行时 | **与音频事件检测共用** `vendor/audio/runtime`，不重复下载 |
| 单帧推理 | **1.9–2.4 秒**（320x320，单线程 WASM，CPU） |
| 线程扩展 | 1 → 16 线程仅 **1.08x** |
| 单图端到端 | 约 2.9 秒（含解码与 alpha 合成） |
| 遮罩质量 | 合成板上为精确分离：主体实心、背景零噪点 |

**16 线程只有 1.08x 是这条路径的性能封顶**，也是不做线程池的依据。由此推出的视频成本：

| mask_fps | 1 分钟 30fps 成片 |
| --- | --- |
| 4 | 约 13 分钟 |
| 8 | 约 26 分钟 |
| 30（逐帧） | 约 52 分钟 |

### 16.4 `mask_fps` 为什么必须是参数

它是"遮罩过渡平滑度 ↔ 渲染耗时"的权衡，取决于镜头里有没有转身、手势、快速运动。
**那是创作判断，归 DSH**——所以计划里有 `mask_fps`，插件执行给定值并回报成本，
而不是内置一个"合理默认"替调用方拍板。

实现上遮罩序列以 `mask_fps` 声明的帧率喂给 ffmpeg，于是每个遮罩被保持到下一个遮罩出现。
低遮罩率的表现是遮罩边缘跳动，这是所选帧率的性质，不是缺陷。

### 16.5 三个必须记住的坑（均已在实现中修正）

1. **抠像必须有背景才有可观察结果。** 链尾的 `format=yuv420p` 会丢弃 alpha；没有背景可合成时
   滤镜等于没生效。所以 `background` 是必需的，缺了**直接报错**而不是静默渲染一张原图。
2. **遮罩序列必须以 `mask_fps` 声明**，不是输出帧率。声明成输出帧率会一个遮罩只够一帧，
   立刻耗尽；声明过高则遮罩抖动，看起来像模型问题。
3. **合成图里的 `lavfi` 背景必须限时长**（`-t`）。无限长的第二输入会让 `overlay` 无休止产帧，
   画面被输出 `-t` 截住而音频耗尽，最终死在 AAC 编码器上并报一句与根因无关的 NaN。

### 16.6 验证

- `tests/matte.test.mjs`（12 例，不需要模型）：`normaliseMask` 对非 0..1 范围的归一、平坦遮罩不产生
  NaN、越界值截断；`maskStatistics` 暴露退化遮罩（全前景/全背景）；`planMasks` 的计数与上限；
  **遮罩序列以 `maskFps` 声明**（这条断言防的是"一个遮罩只够一帧"）；背景必须存在；
  背景输入被 `-t` 限长。
- `tests/matte-engine.test.mjs`（**没有模型时自动跳过**，3 例）：合成板上断言遮罩中心不透明、
  角落透明（不是笼统的"产生了遮罩"——那对全开或全关的坏模型同样成立）；视频产出编号连续的
