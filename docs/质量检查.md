# 质量检查（`video_qc`）

`video_qc` 是 12 个工具之一（重组前为第 9 个工具族），4 个 action（`cases` `check` `structure` `picture`）。它把"这条成片能不能交"写成一份**可执行的用例清单**：每条用例有 id、期望值、严重级别、判定结果，以及支撑这个结果的测量值。

> **字幕回读已迁出（2026-10-04）**：原先这里的 `subtitle_ocr` action 与 `burned_in_readable` 用例（烧录字幕可被 OCR 读回）已随 OCR 能力整体迁到独立插件 **`dsh-ocr`**（`C:\Users\Admin\Documents\GitHub\dsh-ocr`，工具族 `text_*`）。要逐条比对"本该在屏幕上的字"与"实际读回来的字"，用 **`text_read {action:"verify"}`**。本套件保留的 `no_placeholder_text` 读的是 SRT 文件文本，不是像素，所以它没有跟着走。

它和渲染端自带的验收是两件事：

| | `video_inspect {action:"verify"}` | `video_qc {action:"check"}` |
| --- | --- | --- |
| 定位 | 构建的冒烟检查（`deliver` 阶段自动跑） | 独立验收套件 |
| 检查项 | 分辨率、帧率、时长、有无音轨、像素格式、文件大小下限 | 28 条，覆盖容器 / 画面 / 声音 / 旁白时序 / 字幕文本 / 交付物 |
| 期望来源 | 硬编码在 `verifyAgainstPlan` 里 | plan、用例文件、或本文档写明的默认值 |
| 结果形态 | `problems: string[]` | 每条用例 `pass / fail / skip` + `expected` + `actual` + 证据 |
| 能否调 | 不能 | 阈值、严重级别、启停都可以用用例文件调 |

## 判定语义

| 结果 | 含义 |
| --- | --- |
| `pass` | 测量值满足期望 |
| `fail` | 测量值不满足期望；`severity: "error"` 会让整次检查 `ok: false`，`"warn"` 只记录 |
| `skip` | **期望值构不出来，或测量取不到**（没有 plan、容器没有该字段、调用方要求跳过）。`skip` 一定带原因，绝不算通过 |

`strict: true` 时，失败了的 `warn` 也会让整次检查不通过（但计数里它仍是 `warned`）。

这条设计是刻意的：**一份跳过了半数用例的绿色报告，比一份红色的报告更危险**。所以"没 plan"不会让依赖 plan 的用例通过，它会以 `skip` 出现在 `skippedReasons` 里。

## 用例文件

用例文件只能**调整**目录里的用例，不能新增判断：

```jsonc
{
  "cases": {
    "black_frames":      { "enabled": false },
    "frozen_frames":     { "enabled": false },          // 有意做的静止画面
    "letterbox":         { "severity": "error" },        // 这一单要求绝对无黑边
    "loudness_target":   { "severity": "warn" },         // 先记录，不拦交付
    "no_placeholder_text":{ "severity": "warn" }
  }
}
```

也可以整目录调阈值——那是 `check` 的 `thresholds` 参数，不是用例文件的一部分：

```jsonc
{ "action": "check", "target": "out/final.mp4", "plan": "plan.json",
  "thresholds": { "maxBlackRunSeconds": 2, "barLimitFraction": 0.05 } }
```

结果里会回显**合并后**的完整阈值集合。用例文件里出现目录中不存在的 id 会被拒绝（拼错的 id 本来会静默地什么都不调——那正是这套东西要防的失败模式），`only` 里的未知 id 同理。

## action 参考

### `cases`

列出全部用例（id、类别、级别、断言、需要哪些测量、是否被用例文件禁用）以及默认阈值。**不读任何媒体**，用来对着已知 id 写用例文件。

### `check`

```jsonc
{
  "action": "check",
  "target": "out/final.mp4",
  "plan": "plan.json",
  "casesPath": "qc-cases.json",
  "strict": false,
  "picture": true,
  "only": ["audio_duration_matches_picture", "cues_within_audio"],
  "reportPath": "out/qc-report.json"
}
```

返回：

- `ok`、`counts{total, passed, failed, warned, skipped}`
- `failures[]`：失败的用例全文（`expected` / `actual` / `delta` / `detail` / `evidence`）
- `skippedReasons[]`：每条跳过的原因，逐条可读
- `text`：一份测试运行器风格的纯文本报告
- `measurements`：这一轮真正测到的东西（structure / audio / picture / files / narration）
- `thresholds`：合并后的阈值集合

`only` / `skip` 可以只跑关心的几条：只跑 `faststart` 时只做一次 ffprobe，不解码画面、不测响度。

### `structure`

容器事实：每条流的时长/编码/采样率/色彩标记/像素宽高比、容器时长、文件大小、码率，以及 **MP4 顶层 box 顺序**（据此判断 faststart）。音轨提前结束就是在这里被看见的。

### `picture`

固定采样率下的画面事实：黑帧区间、冻帧区间、边缘黑边比例、亮度统计，全部带时间戳。黑帧 = 整帧均值 ≤ `blackLumaThreshold`；冻帧 = 相邻采样帧逐像素完全相同；黑边 = 边缘的行/列**既均匀又明显暗于画面中部**（只满足一条不算）。

### `subtitle_ocr`（已迁出到 `dsh-ocr`）

**这个 action 不在本插件里了。** 烧录字幕的回读现在是独立插件 `dsh-ocr`（`C:\Users\Admin\Documents\GitHub\dsh-ocr`）的 **`text_read {action:"verify"}`**：按 plan 里 `subtitles.source` 指向的 SRT，在字幕应当可见的时刻抽帧读字，逐条给出 `expected` / `read` / `similarity` / `ok` 与 `mismatches`。`burned_in_readable` 用例也一并迁走，本套件不再有它。

下面两条是当年在本仓库实测出来的结论，留作历史记录（实现已随能力迁到 `dsh-ocr`，结论仍然成立）：

- 相似度是逐字符最长公共子序列占比，比较前先做全角转半角、去标点空白——读回来的是字形，不是 SRT 里的逗号。
- **比较对象是"最匹配的那一行"，不是整帧文字。** 这一点对教学类视频是决定性的：画面里常常整屏都是界面文字，只有一行字幕，拿整帧文字去比会把完全烧对字幕的片子算成 0.03。所以每条字幕会与读到的每一行、每相邻两行（字幕折行）以及整帧文本分别比较，取最高分，并把命中的那一行记在 `matchedLine` / `matched` 里。同一帧的整帧读文仍会完整报在 `read` 里，证据不丢。

## 已知边界（不是 bug，是定义）

1. **故意做的静止画面会触发 `frozen_frames`。** 它报的是"这里连续多帧逐像素完全相同"，不是"这里不好看"。用一个静止镜头做长镜头时，请在用例文件里关掉它或把 `maxFrozenRunSeconds` 放大。
2. **纯音乐、无旁白的片子，静音类用例没有意义**：始终有音乐时 `head_silence` / `tail_silence` 都会是 0（这是正确结果，不是漏报）。
3. **烧录字幕的回读已迁出。** 原先的 `burned_in_readable`（需要 OCR 引擎，没装时 `skip`）现在是 `dsh-ocr` 的 `text_read {action:"verify"}`。本套件剩下的 `no_placeholder_text` 只读 SRT 文件文本，不需要任何引擎。
4. **`letterbox` 报的是边缘黑边比例。** 有意的 2.35:1 上下黑边、或画面本身是深色边缘的实拍素材，都会触发它——阈值默认 3%，可在用例文件里按项目调。
5. **`frame_count` 依赖容器写出 `nb_frames`。** 有些封装不写，这时该用例 `skip`，不会误判。
6. **测量是采样，不是逐帧。** 画面类默认 2 fps 采样，比这更短的事件看不见；`probeFps` 可以提高，代价是解码时间。
