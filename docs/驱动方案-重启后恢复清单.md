> 触发原因：启用测试签名需要重启才生效，而重启会终止当时的 DSH 会话。

## 现在处于什么状态

已开启两个引导标志（重启后生效）：

```
testsigning        Yes
nointegritychecks  Yes
```

**为什么必须开**：Windows 从 Vista 起要求内核驱动有有效签名，Interception 的驱动
（`install-interception.exe`）经检验是 `NotSigned`，只能靠测试签名放行。

备份（回滚用，务必保留）：

| 文件 | 用途 |
| --- | --- |
| `vendor/interception/bcd-backup.bcd` | `bcdedit /import` 可完整还原 BCD |
| `vendor/interception/bcd-enum-all.txt` | 可读的 BCD 全文快照 |
| `vendor/interception/pre-reboot-state.json` | 重启前的 IP、启动时间等 |

## 重启后按顺序做

### 第一步：确认机器回来了

```powershell
# 网络接口应自动启动（DHCP）
Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -notlike '127.*' }
# 桌面右下角会显示"测试模式"水印 —— 这是正常的，说明设置生效了
```

### 第二步：一键安装驱动并验证

```powershell
cd C:\Users\Admin\Documents\GitHub\video-factory
powershell -ExecutionPolicy Bypass -File src\bin\driver-setup.ps1
```

脚本会依次：确认测试签名已生效 → 确认备份在位 → 安装驱动 → 验证服务与签名 → 打印回滚命令。

### 第三步：做对比验证（这一步才是真正的证明）

需要证明的是：**同一个控件，`SendInput` 点不中，而驱动级能点中。**

如果驱动级能点中浏览器按钮，兜底方案成立，上层才值得继续做。

## 万一启动异常如何回滚

用任何可用的恢复方式（控制台 / 挂载磁盘 / WinRE）执行：

```
bcdedit /deletevalue testsigning
bcdedit /deletevalue nointegritychecks
```

或从备份完整还原：

```
bcdedit /import "C:\Users\Admin\Documents\GitHub\video-factory\vendor\interception\bcd-backup.bcd"
```

**风险评估**：`testsigning` 只是 BCD 里的一个标志位，不改变引导加载程序本身，因此
启动失败的概率很低；而且本机是 **Legacy BIOS 启动、无安全启动**，不存在与 Secure Boot 冲突的问题。
