# 音频核心模块事故记录（2026-10-04）

2026-10-04 的音频能力迁出（`video-factory` → `dsh-video-audio`）过程中，四个核心模块的内容被毁，
且没有干净副本：

- `src/core/audio-build.mjs`
- `src/core/audio-integrity.mjs`
- `src/core/audio-record.mjs`
- `src/core/audio-restore.mjs`

这四个文件从未提交进 git（`git log --all` 查不到），所以现在的仓库里也没有可回滚的版本。
本仓库里它们只剩占位实现（每个函数都抛错，错误信息指向 `dsh-video-audio/docs/事故记录.md`），
乱码原文保存在 `dsh-video-audio/tmp/mangled/`。

**完整的事故经过、为什么不可恢复、以及重建所需的全部依据，写在
`../dsh-video-audio/docs/事故记录.md`。** 重建之前请先读它。

`audio-measure.mjs` 与 `audio-signal.mjs` 未受影响：本仓库的版本是干净的，且是 `video-factory`
自己需要的（`video_qc {action:"check"}` 用它测量成片的响度、电平、削波与静音）。

教训（迁移类工作通用）：

1. 不要用 `Set-Content -Encoding UTF8` 改写 UTF-8 源文件；Windows PowerShell 5.1 的
   `Get-Content` 按 ANSI 读入，非 ASCII 内容会被毁。批量改写走 Node。
2. 批量改写前，先把「只存在于工作区」的文件提交或另存一份。
3. 改完立刻对所有被改文件跑 `node --check`。
